This page lists every change you notice as an API client, dated by its production deployment. Subscribe via RSS: use the button at the top of the page or `https://docs.trassets.ai/changelog/rss.xml`.

Breaking changes carry the tag **Breaking**. While `/v1/` is a preview, they can land without notice (see [Versioning](/concepts/versioning)).

<Update label="2026-11-02" tags={["Errors"]}>
  - Every response carries the X-Request-ID header. Please include it in support requests, see [Errors](/concepts/errors).
  - If the API cannot look up a table because of a database error, it now answers 500. Before, it wrongly returned 404 "Table not found". A 404 is final again, a 500 is worth a retry.
</Update>

<Update label="2026-11-01" tags={["Breaking", "Pagination"]}>
  - limit on the category endpoints is now at most 10,000, down from 100,000. Larger values return 422. To get more rows, page with next_cursor, see [Pagination](/v1/concepts/pagination).
</Update>

<Update label="2026-10-30" tags={["Breaking", "Pagination", "API keys"]}>
  - total is now null unless you send the new parameter include_total=true. The API counts rows only on request. next_cursor does not depend on it.
  - The OpenAPI spec declares the field types of the v1 resources explicitly instead of inferring them from sample data. total and next_cursor are declared nullable.
  - New API keys start with trs_live_. Existing keys stay valid. The portal shows when each key was last used.
  - When creating a key in the portal, access can be restricted to positions of the Trassets-Standard reporting structure, see [Authentication](/v1/authentication).
</Update>

<Update label="2026-10-29" tags={["Rate limits"]}>
  - Each API key has a budget of 2,500 requests per hour, shared across all /v1/ endpoints. Failed key checks do not count. See [Rate limits](/concepts/rate-limits).
</Update>

<Update label="2026-10-27" tags={["Breaking", "Data model"]}>
  - All endpoints now live under /v1/: category tables, raw tables, catalog, and changes. Unversioned paths return 404 without a redirect. Offset pagination and the X- pagination headers are gone, paging uses cursor. See [Versioning](/concepts/versioning).
  - New category kpi with property KPIs (property_kpis, property_kpis_by_floor_area_type), see [KPI](/v1/data-model/kpi). Since October 28, /v1/changes can filter by this category too.
</Update>

<Update label="2026-10-26" tags={["Filtering"]}>
  - Filters on columns with object values, such as account_type on property_structure, now return matches instead of 500. You filter by code or label. A filter value that does not fit the column type returns 400 instead of 500.
</Update>

<Update label="2026-10-16" tags={["Breaking", "Data model"]}>
  - Decimal columns under /v1/ come as JSON numbers instead of strings, for example 19.0 instead of "19.0000".
  - More free-text and assignee columns count as personal data and now require the matching grant, among them comment, responsible_user, and responsible_person. See [Authentication](/v1/authentication).
</Update>

<Update label="2026-10-13" tags={["API keys"]}>
  - API keys can have an expiry date, set in the portal. An expired key returns 401 "API key expired".
</Update>
