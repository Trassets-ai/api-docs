The Trassets MCP server lets AI clients read your Data API v1 data through the [Model Context Protocol](https://modelcontextprotocol.io). Every call runs with your API key and is subject to the same restrictions, grants, and rate limit as a direct API request.

## What the MCP server can do

The server offers five tools. All of them only read data; each one calls a Data API endpoint with your key.

| Tool | What it does | API endpoint |
| --- | --- | --- |
| `list_catalog` | Lists the categories and tables your key may read. | `GET /v1/catalog` |
| `get_table_data` | Reads one page of a table, filtered by exact values such as `property_id`. Some tables require a filter (see [Filtering](/v1/concepts/filtering)). | `GET /v1/{category}/{table}` |
| `get_changes` | Lists the tables whose data changed since a point in time, at most 120 days back. | `GET /v1/changes` |
| `list_raw_tables` | Lists the raw tables synced from your source systems. Empty for keys without raw access. | `GET /v1/raw/tables` |
| `get_raw_table` | Reads one page of a raw table. Needs a key of type `raw` with both personal data grants (see [Key types](/v1/authentication#key-types)). | `GET /v1/raw/{table_name}` |

## Endpoint and key

| Setting | Value |
| --- | --- |
| URL | `https://mcp.trassets.ai/mcp` |
| Transport | Streamable HTTP |
| Authentication | `X-API-Key: <key>` or `Authorization: Bearer <key>` on every request |

You need a key with channel **MCP**. An administrator creates it in the [portal](https://portal.api.trassets.ai) like any other key (see [Authentication](/v1/authentication#channel)) and selects **MCP** under **Channel**. A key works for exactly one channel: the MCP server rejects keys created for the API, and the REST API rejects MCP keys.

<Warning>
  Data that a tool returns is processed by the model provider of your AI client. Only connect clients whose provider your organization has approved for this data, and don't combine the MCP server with tools that can send data to third parties. See [Risks](#risks).
</Warning>

## Supported AI clients

MCP is model-independent: the client brings the model, so the model that answers depends on your client. What matters is whether the client can send a fixed API key header to a remote MCP server. The MCP server does not support OAuth sign-in yet, so clients that only offer OAuth can't connect.

As of November 2026. Vendors change their MCP support often; if a step doesn't match, check the client's documentation.

| Client | Supported | Where the key goes |
| --- | --- | --- |
| Claude Code | Yes | `--header` in `claude mcp add` (see below) |
| Cursor | Yes | `headers` in `.cursor/mcp.json` |
| VS Code (GitHub Copilot agent mode) | Yes | `headers` in `.vscode/mcp.json` |
| OpenAI Codex CLI | Yes | `bearer_token_env_var` in `~/.codex/config.toml` |
| Gemini CLI | Yes | `headers` in `~/.gemini/settings.json` |
| Microsoft Copilot Studio | Yes | Authentication **API key**, type **Header**, header name `X-API-Key` (see below) |
| Claude (claude.ai, Claude Desktop) as custom connector | Limited | Only if your organization sees the **Request headers** option (beta); otherwise use Claude Code |
| ChatGPT | Not yet | Custom connectors require OAuth |
| Microsoft 365 Copilot (declarative agents) | Not yet | MCP plugins require OAuth |

## Example: Claude Code

```bash
claude mcp add --transport http trassets https://mcp.trassets.ai/mcp \
  --header "X-API-Key: $TRASSETS_MCP_KEY"
```

Then ask Claude Code which Trassets tables it can read. Other clients need the same two values: the URL and the key, sent as `X-API-Key` header or as `Authorization: Bearer <key>`. Don't put the plaintext key into a config file you commit: Cursor resolves `${env:TRASSETS_MCP_KEY}` in `headers`, and VS Code prompts for it through `${input:...}`.

## Example: Microsoft Copilot Studio

1. Open your agent, go to **Tools**, select **Add a tool**, and add a new Model Context Protocol server.
2. Enter a name, a description, and `https://mcp.trassets.ai/mcp` as server URL.
3. Under authentication, choose **API key**, type **Header**, and enter `X-API-Key` as header name.
4. Create a connection, enter your MCP key, and select **Add to agent**. All five tools are enabled by default.
5. Before you publish the agent, check which credentials the tool uses. With maker-provided credentials, everyone who uses the agent reads with your key and sees everything your key may see. Instead, have an administrator create one MCP key per user and let each user connect with their own key.

Then ask the agent, for example, "Which Trassets tables can you read?" or "How many properties are in the data?"

## Example prompts

Three tasks that work with the v1 tables. The prompts name the tables so the model doesn't have to guess. Replace `<property_id>` and the reference date (first day of a month).

**Property fact sheet**

```text
Create a fact sheet for property <property_id> as of 2026-11-01.
Take master data from property/properties, buildings and units from property/property_structure,
floor area, vacancy, and net rent from kpi/property_kpis_by_floor_area_type
(filter property_id and reference_date), and technical equipment from property/technical_objects.
Don't recompute figures; take them from the KPI tables.
```

**Vacancy list**

```text
Create a vacancy list as of 2026-11-01 from kpi/property_kpis (filter reference_date):
all properties with vacancy, sorted by vacant floor area in sqm.
Then list the vacant units of the three properties with the largest vacancy:
units from property/property_structure, leases from stakeholder/tenants, each filtered by property_id.
A unit is vacant if no lease (contract_period) runs on the reference date.
```

**Sales brochure**

```text
Draft a sales brochure for property <property_id>. Take location and construction year from
property/properties, units, market rent, and the property photo (column url) from
property/property_structure, and the letting status from kpi/property_kpis_by_floor_area_type.
Don't name tenants or other people. Mark everything that doesn't come from the data as a placeholder.
```

The prompts hit these limits:

- Vacant units for the whole portfolio at once: the model would have to read every row of `property_structure` and `tenants`, several thousand for a mid-sized portfolio. That doesn't fit into a chat's context. Ask property by property instead.
- There's at most one photo per property (`url`). The MCP server doesn't provide logos, colors, energy certificates, floor plans, or descriptions; the brochure needs placeholders for them.

## Limits

- **Read only.** The server can't create or change data.
- **No calculations.** Tools return rows, not sums, averages, or KPIs. If you ask for a total, the model in your client computes it from the rows it has read, and it can miscount or stop after one page. For row counts, the tools return `total`. Pre-computed figures are only those in the [KPI tables](/v1/data-model/kpi).
- **Small pages.** A tool call returns at most 200 rows (default 50). Reading a large table takes many calls, and each call counts against your key's budget of 2,500 requests per hour (see [Rate limits](/concepts/rate-limits)). For full exports, use the REST API with a separate key for channel API (see [Pagination](/v1/concepts/pagination)).
- **Exact filters only.** `get_table_data` filters by exact value on a table's filter columns. Ranges and text search are not available.
- **Data freshness.** The data is as current as the last sync of each table; there is no fixed interval. `get_changes` shows `last_sync_at` per table (see [Sync cycle](/concepts/sync-cycle)).
- **API key only.** There is no OAuth sign-in yet (see [Supported AI clients](#supported-ai-clients)).

## Risks

- **Data leaves Trassets.** Everything a tool returns goes to the model provider of your client and is processed under the provider's terms. Your organization decides which provider may process which data. Use keys without the [personal data grants](/v1/authentication#personal-data-grants) unless the use case needs them.
- **Instructions hidden in data.** Free-text fields such as comments or booking texts can contain text that reads like an instruction. The tools tell the model to ignore such text, but no model follows that reliably.
- **Outbound tools.** An agent that reads your data, processes such text, and can also send data out (email, web requests, file uploads, MCP servers that write elsewhere) can be tricked into sending your data to third parties. Use the Trassets MCP server only in agents and sessions without such tools.
- **Unverified answers.** The model can misread fields, mix up tables, or extrapolate from one page. Check figures against the API or your reports before you rely on them.
- **One key per person.** Create one MCP key per person, name it after them in the portal, and don't share it, not even through an agent that others use. When someone leaves, delete their key; that ends their MCP access.

## Error messages

Tools report errors as text. The most common ones:

| Message | Meaning |
| --- | --- |
| Missing API key. Send it in the X-API-Key header or as Authorization: Bearer \<key\>. | The client sends no key. Check the header configuration. |
| API key is missing or expired. | The key has expired. Create a new one in the portal. |
| API key is invalid, disabled, or not permitted to access this resource. | The key is unknown or disabled, was created for channel API instead of MCP, or may not read this table. |
| Table is unknown or not released in v1 for this customer. | The table doesn't exist for your organization. Call `list_catalog` for the available tables. |
| Invalid request: … | The Data API rejected the request, for example because of an unknown or missing required filter or a `since` more than 120 days back. The rest of the message says why. |
| Rate limit reached. Retry after N seconds. | Your key's hourly budget is used up. |
| Data API error. Try again later. Request ID: … | Temporary server error. If it persists, contact support and quote the Request ID (see [Errors](/concepts/errors#contacting-support)). |
| Data API did not respond in time. / Data API is not reachable. | Temporary problem. Try again later. |
| Data was re-synced during pagination. Restart without cursor. | The table was refreshed while paging. Read it again from the first page. |
