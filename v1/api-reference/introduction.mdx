The `/v1/` endpoints are the versioned interface to the same real-estate data. Base URL: `https://api.trassets.ai`. Send your API key in the `X-API-Key` header on every request. All responses are JSON.

Every `/v1/{category}/{api_table}` response is a JSON object with the rows in `data` and the pagination fields next to it (see [Pagination](#pagination)). See [Response Structure](/v1/response-shape-conventions) for the object, array, and code/label patterns the rows follow.

## Endpoint types

| Type | Path pattern | Pagination | Use case |
| --- | --- | --- | --- |
| Category endpoints | `/v1/{category}/{api_table}` | Cursor-based (`limit` / `cursor`, `next_cursor` in body) | Business queries, dashboards, incremental fetches |
| Raw endpoints | `/v1/raw/{table_name}` (or `/raw/{table_name}`) | Cursor-based (`cursor` from `next_cursor` in body) | Bulk sync, full exports, data warehousing |

Raw endpoints are generic per customer (no per-table content review), so both the unversioned and `/v1/` path always expose the same tables. The `/v1/` path uses the same response keys as the category endpoints (`total`); the unversioned path keeps `total_rows`.

### Pagination

`/v1/` is cursor-only. The pagination fields are part of the response body — there are no `X-Total-Count` / `X-Has-More` / `X-Next-*` headers and no `offset` parameter (a request with `offset` returns `400`).

```json
{
  "data": [ { "…": "…" } ],
  "count": 1000,
  "next_cursor": "eyJjb2wiOiAi…",
  "total": 167953
}
```

- `data` — the rows of this page
- `count` — number of rows in `data`
- `next_cursor` — opaque cursor for the next page; `null` on the last page. Pass it unchanged as the `cursor` query parameter; omit `cursor` for the first page.
- `total` — rows matching the query from the cursor position onward (on the first page: all matching rows)

Loop until `next_cursor` is `null`. `/v1/raw/{table_name}` uses the same keys and adds `table_name`.

<Note>
  `/v1/` is a preview: the response envelope and pagination changed during the preview and may change again.
  The unversioned endpoints are unaffected — they keep the array response with `X-*` headers and `offset`, see [Pagination](/concepts/pagination).
</Note>

## Error format

Errors follow [RFC 7807](https://datatracker.ietf.org/doc/html/rfc7807) (`application/problem+json`). Every error object contains `type`, `title`, `status`, `detail`, and `instance`. See [Errors](/concepts/errors) for a full list of status codes and retry guidance.

## Versioning

Tables are migrated to `/v1/` one at a time. See [Versioning](/concepts/versioning) for the current rollout state.

## Endpoint groups without a version prefix

Three endpoint groups exist once for the whole API and carry no `/v1/` prefix. They are listed in the sidebar below the categories.

| Group | Endpoint | What to expect under `/v1/` |
| --- | --- | --- |
| Catalog | `GET /catalog` | Lists all categories and tables exposed by the API. Use [Data Model Overview](/v1/data-model/overview) for the `/v1/` inventory. |
| Delta Sync | `GET /changes` | Reports sync timestamps per table. Requires a `since` parameter (ISO-8601 UTC). |
| Raw Data | `GET /raw/tables`, `GET /raw/{table_name}` | Source tables below the modelled layer. Also available under `/v1/raw/tables` / `/v1/raw/{table_name}` — same data either way. |
