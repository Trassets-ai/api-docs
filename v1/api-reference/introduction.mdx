The `/v1/` endpoints are the versioned interface to the same real-estate data. Base URL: `https://api.trassets.ai`. Send your API key in the `X-API-Key` header on every request. All responses are JSON.

Every `/v1/{category}/{api_table}` response is a JSON object with the rows in `data` and the pagination fields next to it. See [Response Structure](/v1/response-shape-conventions) for the object, array, and code/label patterns the rows follow.

## Endpoint types

| Type | Path pattern | Pagination | Use case |
| --- | --- | --- | --- |
| Category endpoints | `/v1/{category}/{api_table}` | Cursor-based (`limit` / `cursor`, `next_cursor` in body) | Business queries, dashboards, incremental fetches |
| Raw endpoints | `/v1/raw/{table_name}` (or `/raw/{table_name}`) | Cursor-based (`cursor` from `next_cursor` in body) | Bulk sync, full exports, data warehousing |

Raw endpoints are generic per customer (no per-table content review), so `/v1/raw/` and `/raw/` always expose the same tables. The `/v1/` path uses the same response keys as the category endpoints (`total`); `/raw/` uses `total_rows`.

### Pagination

Cursor-only, with the pagination fields in the body instead of headers. Coming from the unversioned API: `X-Total-Count` → `total`, `X-Has-More` and `X-Next-Cursor` → `next_cursor` (`null` = no further page), `X-Next-Offset` → none, `/v1/` has no `offset`. Details: [Pagination](/v1/concepts/pagination).

## Error format

Errors follow [RFC 7807](https://datatracker.ietf.org/doc/html/rfc7807) (`application/problem+json`). Every error object contains `type`, `title`, `status`, `detail`, and `instance`. See [Errors](/concepts/errors) for a full list of status codes and retry guidance.

## Versioning

Breaking changes never land on a published path. See [Versioning](/concepts/versioning).

## Endpoint groups without a version prefix

Three endpoint groups exist once for the whole API and carry no `/v1/` prefix. Catalog and Delta Sync are listed in the sidebar below the categories.

| Group | Endpoint | What to expect under `/v1/` |
| --- | --- | --- |
| Catalog | `GET /catalog` | Lists all categories and tables exposed by the API. Use [Data Model Overview](/v1/data-model/overview) for the `/v1/` inventory. |
| Delta Sync | `GET /changes` | Reports sync timestamps per table. Requires a `since` parameter (ISO-8601 UTC). |
| Raw Data | `GET /raw/tables`, `GET /raw/{table_name}` | Source tables below the modelled layer. Same data as `/v1/raw/tables` / `/v1/raw/{table_name}`, documented in the **Endpoints** group. |
