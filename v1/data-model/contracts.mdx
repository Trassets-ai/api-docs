The v1 Contracts domain covers four tables: `service_contracts`, `contract_debits`,
`contract_debit_diffs`, and `contract_ends`, all of which follow the [response
structure](/v1/response-shape-conventions) rules.

## service_contracts

`GET /v1/contracts/service_contracts` — maintenance and service contracts.

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="creditor_id" type="string" required>
  Identifies the service provider. References `Stakeholder.creditor` — see the
  [Stakeholder field reference](/v1/data-model/stakeholder).
</ResponseField>

<ResponseField name="creditor_name" type="string">
  Display name of the service provider. `null` in most rows — join through `creditor_id`
  for a reliable name instead.
</ResponseField>

<ResponseField name="contract_id" type="string" required>
  Contract identifier, a formatted string (e.g. `"2019/00015"`). Referenced by
  [`Property.technical_objects.service_contract_id`](/v1/data-model/property), which is how
  you find the contract covering a given elevator, heating system, or other installation.
</ResponseField>

<ResponseField name="contract_number" type="string">
  Human-readable contract number.
</ResponseField>

<ResponseField name="contract_name" type="string">
  Contract name.
</ResponseField>

<ResponseField name="contract_category" type="string">
  Contract category.
</ResponseField>

<ResponseField name="contract_type" type="string">
  Contract type.
</ResponseField>

<ResponseField name="contract_period" type="object">
  Contract term — `{start, end}` (date strings).
</ResponseField>

<ResponseField name="contract_value" type="string">
  Contract value. Decimal value serialized as a string (e.g. `"0.0000"`), not a JSON
  number — cast before doing arithmetic on it.
</ResponseField>

<ResponseField name="contract_value_year" type="string">
  Contract value normalised to an annual figure. Decimal value serialized as a string, same
  as `contract_value`.
</ResponseField>

<ResponseField name="contract_reasoning" type="string">
  Reason code for the contract.
</ResponseField>

<ResponseField name="contract_reasoning_comment" type="string">
  Free-text comment on the contract reasoning.
</ResponseField>

## contract_debits

`GET /v1/contracts/contract_debits` — rental debit positions as a time series. Each record
represents a scheduled debit with a validity interval.

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="floor_area_id" type="string">
  References the unit in [`Property.property_structure`](/v1/data-model/property#property_structure).
  A string here, while `property_structure.floor_area_id` is an integer — cast before
  joining.
</ResponseField>

<ResponseField name="tenancy_id" type="string">
  Identifies the tenancy this debit applies to. Same value as
  [`Stakeholder.tenants.tenancy_id`](/v1/data-model/stakeholder) — join directly on this
  field.
</ResponseField>

<ResponseField name="property_id_person_id" type="integer">
  Composite key identifying the tenant this debit applies to. It resembles a concatenation
  of `property_id` and a person number, but isn't always exactly that — use the field as
  given rather than deriving it yourself. Use `tenancy_id` above to reach the tenant
  instead.
</ResponseField>

<ResponseField name="ledger_id" type="string">
  Ledger account (`Sachkonto`) the debit type books to.
</ResponseField>

<ResponseField name="debit_period" type="object">
  Validity interval of the debit — `{start, end}` (date strings). `end` is omitted (not
  `null`) while the interval is still open.
</ResponseField>

<ResponseField name="due_date_day" type="integer">
  Day of the month the debit is due. `null` where the source system has no due day set.
</ResponseField>

<ResponseField name="debit_type" type="object">
  Category of the debit — `{code, label}` (e.g. `{"code": 11, "label": "Nettokaltmiete
  Wohnung"}`).
</ResponseField>

<ResponseField name="debit_amount" type="string" required>
  The debit amount for the validity interval. Decimal value serialized as a string, not a
  JSON number — cast before doing arithmetic on it.
</ResponseField>

<ResponseField name="account_group" type="string">
  Account group assignment. Related to, but not derived from, `kontenmapping_ranges`.
</ResponseField>

<ResponseField name="state" type="string">
  Status of the debit record.
</ResponseField>

<ResponseField name="tax_type" type="boolean">
  Whether this debit type is VAT-relevant.
</ResponseField>

<ResponseField name="net_rent" type="boolean">
  Whether this debit type is classified as net rent, based on the account range configured
  for this tenant.
</ResponseField>

<ResponseField name="side_costs" type="boolean">
  Whether this debit type is classified as an ancillary (side) cost, based on the account
  range configured for this tenant.
</ResponseField>

## contract_debit_diffs

`GET /v1/contracts/contract_debit_diffs` — monthly deviations between the debit target and
the actual account movements. Use this to reconcile planned debits against realised cash
flow.

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="debit_diff_value" type="object">
  Deviation amount — `{net, tax, gross}`.
</ResponseField>

<ResponseField name="person_id" type="string">
  Tenant or contact person linked to the deviation, using a local per-property numbering
  scheme — join on `property_id` **and** `person_id` together, the same as
  [`Accounting.booking_header.person_id`](/v1/data-model/accounting).
</ResponseField>

<ResponseField name="account_id" type="integer">
  Ledger account the deviation applies to. Joins to
  [`Accounting.accounts.account_id`](/v1/data-model/accounting).
</ResponseField>

<ResponseField name="valid_from" type="date" required>
  Month the deviation applies to.
</ResponseField>

<ResponseField name="debit_diff_reminder_from" type="date">
  Date from which a payment reminder applies to this deviation, if any.
</ResponseField>

<ResponseField name="debit_diff_reminder_manual" type="boolean">
  Whether the reminder date above was set manually rather than by the automated reminder
  run.
</ResponseField>

## contract_ends

`GET /v1/contracts/contract_ends` — lease end dates and extension/option handling. Use this
to track upcoming expiries, deadlines for exercising options, and the current exercise
status.

<Note>
  This endpoint requires a `property_id` query parameter — a request without it returns
  `400 Bad Request`. It's the only `/v1/` endpoint with a mandatory filter.
</Note>

<ResponseField name="tenancy_id" type="string" required>
  Identifies the tenancy this record applies to. Same value as
  [`Stakeholder.tenants.tenancy_id`](/v1/data-model/stakeholder) and this table's own
  `contract_debits.tenancy_id` — join directly on this field.
</ResponseField>

<ResponseField name="floor_area_id" type="integer">
  References the unit in [`Property.property_structure`](/v1/data-model/property#property_structure).
</ResponseField>

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="contract_end_id" type="string" required>
  Identifier for this specific option/renewal entry — a tenancy can have several.
  Deterministic for unchanged source data, but not stable across the record's lifecycle: it
  is derived from fields like `option_deadline` and the lease end date, so it changes if
  either is later revised.
</ResponseField>

<ResponseField name="period" type="object">
  Lease term — `{start, end}` (date strings). `end` is the effective contract end date
  after applying any option logic, not the raw contractual end date. A missing key (rather
  than `null`) means that boundary isn't set.
</ResponseField>

<ResponseField name="option_state" type="object">
  Extension option status — `{code, label}` (codes: `1` = Offen, `2` = Ausgeübt, `3` =
  Nicht ausgeübt, `4` = Abgelaufen). `{}` where no option entry exists for this record —
  treat that the same as no code/label.
</ResponseField>

<ResponseField name="option_remarks" type="string[]">
  Free-text remarks on the option, as an array with one entry per remark. Empty where none
  exist.
</ResponseField>

<ResponseField name="contract_end_new" type="date">
  Undocumented. Contact support before relying on it.
</ResponseField>

<ResponseField name="contract_prolongation_months" type="integer">
  Extension length in months.
</ResponseField>

<ResponseField name="request_date" type="date">
  Date the tenant was asked to decide on an extension option.
</ResponseField>

<ResponseField name="response_deadline" type="date">
  Deadline for the tenant's response.
</ResponseField>

<ResponseField name="tenant_response_date" type="date">
  Date the tenant actually responded.
</ResponseField>

<ResponseField name="response_type" type="integer">
  Undocumented. Contact support before relying on it.
</ResponseField>

<ResponseField name="option_deadline" type="date">
  Deadline by which an extension option must be exercised.
</ResponseField>

<ResponseField name="deadline_lead_time" type="integer">
  Undocumented. Contact support before relying on it.
</ResponseField>

<ResponseField name="auto_use_option" type="boolean">
  Whether the option is exercised automatically if the tenant does not respond.
</ResponseField>

<ResponseField name="options_used" type="integer">
  Number of extension options already used.
</ResponseField>

<ResponseField name="options_not_used" type="integer">
  Number of extension options still available.
</ResponseField>

<ResponseField name="is_terminated" type="boolean">
  Whether a termination reason is on file for this lease.
</ResponseField>

<ResponseField name="termination_reason" type="string">
  Termination reason, if the lease has been terminated.
</ResponseField>
