The v1 Contracts domain covers five tables: `service_contracts`, `contract_debits`,
`contract_debit_diffs`, `contract_ends`, and `index_rent`, all of which follow the [response
structure](/v1/response-shape-conventions) rules.

## service_contracts

`GET /v1/contracts/service_contracts` — maintenance and service contracts.

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="creditor_id" type="string" required>
  Identifies the service provider. References `Stakeholder.creditor` — see the
  [Stakeholder field reference](/v1/data-model/stakeholder).
</ResponseField>

<ResponseField name="creditor_name" type="string">
  Display name of the service provider. `null` in most rows — join through `creditor_id`
  for a reliable name instead.
</ResponseField>

<ResponseField name="contract_id" type="string" required>
  Contract identifier, a formatted string (e.g. `"2019/00015"`). Referenced by
  [`Property.technical_objects.service_contract_id`](/v1/data-model/property), which is how
  you find the contract covering a given elevator, heating system, or other installation.
</ResponseField>

<ResponseField name="contract_number" type="string">
  Human-readable contract number.
</ResponseField>

<ResponseField name="contract_name" type="string">
  Contract name.
</ResponseField>

<ResponseField name="contract_category" type="string">
  Contract category.
</ResponseField>

<ResponseField name="contract_type" type="string">
  Contract type.
</ResponseField>

<ResponseField name="contract_period" type="object">
  Contract term — `{start, end}` (date strings).
</ResponseField>

<ResponseField name="contract_value" type="string">
  Contract value. Decimal value serialized as a string (e.g. `"0.0000"`), not a JSON
  number — cast before doing arithmetic on it.
</ResponseField>

<ResponseField name="contract_value_year" type="string">
  Contract value normalised to an annual figure. Decimal value serialized as a string, same
  as `contract_value`.
</ResponseField>

<ResponseField name="contract_reasoning" type="string">
  Reason code for the contract.
</ResponseField>

<ResponseField name="contract_reasoning_comment" type="string">
  Free-text comment on the contract reasoning.
</ResponseField>

## contract_debits

`GET /v1/contracts/contract_debits` — rental debit positions as a time series. Each record
represents a scheduled debit with a validity interval.

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="floor_area_id" type="string">
  References the unit in [`Property.property_structure`](/v1/data-model/property#property_structure).
  A string here, while `property_structure.floor_area_id` is an integer — cast before
  joining.
</ResponseField>

<ResponseField name="floor_area_person_id" type="string">
  Identifies the tenancy this debit applies to. Same value and same type as
  [`Stakeholder.tenants.floor_area_person_id`](/v1/data-model/stakeholder) — join directly, no
  cast needed.
</ResponseField>

<ResponseField name="property_id_person_id" type="integer">
  Composite key identifying the tenant this debit applies to. It resembles a concatenation
  of `property_id` and a person number, but isn't always exactly that — use the field as
  given rather than deriving it yourself. Use `floor_area_person_id` above to reach the
  tenant instead — that one is a documented join key.
</ResponseField>

<ResponseField name="ledger_id" type="string">
  Ledger account (`Sachkonto`) the debit type books to.
</ResponseField>

<ResponseField name="debit_period" type="object">
  Validity interval of the debit — `{start, end}` (date strings). `end` is omitted (not
  `null`) while the interval is still open.
</ResponseField>

<ResponseField name="due_date_day" type="integer">
  Day of the month the debit is due. `null` where the source system has no due day set.
</ResponseField>

<ResponseField name="debit_type" type="object">
  Category of the debit — `{code, label}` (e.g. `{"code": 11, "label": "Nettokaltmiete
  Wohnung"}`).
</ResponseField>

<ResponseField name="debit_amount" type="string" required>
  The debit amount for the validity interval. Decimal value serialized as a string, not a
  JSON number — cast before doing arithmetic on it.
</ResponseField>

<ResponseField name="account_group" type="string">
  Account group assignment. Related to, but not derived from, `kontenmapping_ranges`.
</ResponseField>

<ResponseField name="state" type="string">
  Status of the debit record.
</ResponseField>

<ResponseField name="tax_type" type="boolean">
  Whether this debit type is VAT-relevant.
</ResponseField>

<ResponseField name="net_rent" type="boolean">
  Whether this debit type is classified as net rent, based on the account range configured
  for this tenant.
</ResponseField>

<ResponseField name="side_costs" type="boolean">
  Whether this debit type is classified as an ancillary (side) cost, based on the account
  range configured for this tenant.
</ResponseField>

## contract_debit_diffs

`GET /v1/contracts/contract_debit_diffs` — monthly deviations between the debit target and
the actual account movements. Use this to reconcile planned debits against realised cash
flow.

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="debit_diff_value" type="object">
  Deviation amount — `{net, tax, gross}`.
</ResponseField>

<ResponseField name="person_id" type="string">
  Tenant or contact person linked to the deviation, using a local per-property numbering
  scheme — join on `property_id` **and** `person_id` together, the same as
  [`Accounting.booking_header.person_id`](/v1/data-model/accounting).
</ResponseField>

<ResponseField name="account_id" type="integer">
  Ledger account the deviation applies to. Joins to
  [`Accounting.accounts.account_id`](/v1/data-model/accounting).
</ResponseField>

<ResponseField name="valid_from" type="date" required>
  Month the deviation applies to.
</ResponseField>

<ResponseField name="debit_diff_reminder_from" type="date">
  Date from which a payment reminder applies to this deviation, if any.
</ResponseField>

<ResponseField name="debit_diff_reminder_manual" type="boolean">
  Whether the reminder date above was set manually rather than by the automated reminder
  run.
</ResponseField>

## contract_ends

`GET /v1/contracts/contract_ends` — lease end dates and extension/option handling. Use this
to track upcoming expiries, deadlines for exercising options, and the current exercise
status.

<Note>
  This endpoint requires a `property_id` query parameter — a request without it returns
  `400 Bad Request`. It's the only `/v1/` endpoint with a mandatory filter.
</Note>

<ResponseField name="floor_area_person_id" type="string" required>
  Identifies the tenancy this record applies to. Same value and same type as
  [`Stakeholder.tenants.floor_area_person_id`](/v1/data-model/stakeholder) and this domain's
  own `contract_debits.floor_area_person_id` — join directly on either, no cast needed.
</ResponseField>

<ResponseField name="floor_area_id" type="integer">
  References the unit in [`Property.property_structure`](/v1/data-model/property#property_structure).
</ResponseField>

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="contract_end_id" type="string" required>
  Identifier for this specific option/renewal entry — a tenancy can have several.
  Deterministic for unchanged source data, but not stable across the record's lifecycle: it
  is derived from fields like `option_deadline` and the lease end date, so it changes if
  either is later revised.
</ResponseField>

<ResponseField name="period" type="object">
  Lease term — `{start, end}` (date strings). `end` is the effective contract end date
  after applying any option logic, not the raw contractual end date. A missing key (rather
  than `null`) means that boundary isn't set.
</ResponseField>

<ResponseField name="option_state" type="object">
  Extension option status — `{code, label}` (codes: `1` = Offen, `2` = Ausgeübt, `3` =
  Nicht ausgeübt, `4` = Abgelaufen). `{}` where no option entry exists for this record —
  treat that the same as no code/label.
</ResponseField>

<ResponseField name="option_remarks" type="string[]">
  Free-text remarks on the option, as an array with one entry per remark. Empty where none
  exist.
</ResponseField>

<ResponseField name="contract_end_new" type="date">
  Undocumented. Contact support before relying on it.
</ResponseField>

<ResponseField name="contract_prolongation_months" type="integer">
  Extension length in months.
</ResponseField>

<ResponseField name="request_date" type="date">
  Date the tenant was asked to decide on an extension option.
</ResponseField>

<ResponseField name="response_deadline" type="date">
  Deadline for the tenant's response.
</ResponseField>

<ResponseField name="tenant_response_date" type="date">
  Date the tenant actually responded.
</ResponseField>

<ResponseField name="response_type" type="integer">
  Undocumented. Contact support before relying on it.
</ResponseField>

<ResponseField name="option_deadline" type="date">
  Deadline by which an extension option must be exercised.
</ResponseField>

<ResponseField name="deadline_lead_time" type="integer">
  Undocumented. Contact support before relying on it.
</ResponseField>

<ResponseField name="auto_use_option" type="boolean">
  Whether the option is exercised automatically if the tenant does not respond.
</ResponseField>

<ResponseField name="options_used" type="integer">
  Number of extension options already used.
</ResponseField>

<ResponseField name="options_not_used" type="integer">
  Number of extension options still available.
</ResponseField>

<ResponseField name="is_terminated" type="boolean">
  Whether a termination reason is on file for this lease.
</ResponseField>

<ResponseField name="termination_reason" type="string">
  Termination reason, if the lease has been terminated.
</ResponseField>

## index_rent

`GET /v1/contracts/index_rent` — index-linked rent adjustment agreements (`Indexmiete`): which
consumer price index a rent is tied to, the thresholds and rules that trigger an adjustment,
and the validity window of each agreed state. One row per tenancy × debit type × index state;
superseded states stay in the table, so filter on `is_current` for the state in force today.

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="floor_area_person_id" type="string" required>
  Identifies the tenancy this agreement applies to. Same value and same type as
  [`Stakeholder.tenants.floor_area_person_id`](/v1/data-model/stakeholder),
  `contract_debits.floor_area_person_id`, and `contract_ends.floor_area_person_id` — join
  directly on any of them, no cast needed.
</ResponseField>

<ResponseField name="validity_period" type="object">
  Validity interval of this index state — `{start, end}` (date strings). `end` is
  `"9999-12-31"` (a sentinel, not `null`) while the state is still open, which is the case for
  every row where `is_current` is `true`.
</ResponseField>

<ResponseField name="calculation_model" type="object">
  Rule that determines when an adjustment takes effect — `{code, label}`. Codes: `1` = nach BGB
  ($557b), `2` = Ab Berechnungsdatum (beide Bedingungen), `3` = Ab Berechnungsdatum (mindestens
  eine Bedingung), `4` = Ab Mitteilungsdatum (beide Bedingungen), `5` = Ab Mitteilungsdatum
  (mindestens eine Bedingung), `6` = zum nächsten Quartal (beide Bedingungen), `7` = zum
  nächsten Quartal (mindestens eine Bedingung). `code` `0` means no model is set in the source
  system and comes with `label: null`.
</ResponseField>

<ResponseField name="is_current" type="boolean">
  Whether this is the state currently in force. `false` marks a superseded state kept for
  history.
</ResponseField>

<ResponseField name="account_id" type="integer">
  The debit type (`Sollart`) the index agreement applies to — the same code as
  [`contract_debits.debit_type.code`](#contract_debits) (e.g. `11` = Nettokaltmiete Wohnung,
  `12` = Gewerbemiete (m. USt.)). Despite the name it is **not** a ledger account and does not
  join to [`Accounting.accounts.account_id`](/v1/data-model/accounting), even though both are
  integers — see the [Field Glossary](/v1/data-model/field-glossary).
</ResponseField>

<ResponseField name="index_name" type="string">
  Name of the price index the rent is tied to, as maintained in the source system (e.g.
  `"VPI 2020"`, `"Verbraucherpreisindex"`). Free text, not a fixed code list, and `null` where
  no index is named.
</ResponseField>

<ResponseField name="base_year" type="integer">
  Base year of that index (e.g. `2020`).
</ResponseField>

<ResponseField name="index_value_used" type="string">
  Index value at the start of the index reference, used as the basis for comparison. Decimal
  value serialized as a string, not a JSON number — cast before doing arithmetic on it. `null`
  where the index series holds no value for that month.
</ResponseField>

<ResponseField name="min_date" type="date">
  Start of the contract-aligned validity window. Same as `validity_period.start`, except on the
  earliest state of a tenancy, where it reaches back to `begin_contract` if the contract started
  first.
</ResponseField>

<ResponseField name="max_date" type="date">
  End of the contract-aligned validity window: `validity_period.end` capped at `end_contract`.
  `"9999-12-31"` where the state is open and no contract end is on file. Use
  `min_date`/`max_date` for gap-free day coverage across a tenancy, and `validity_period` for
  the raw state boundaries.
</ResponseField>

<ResponseField name="begin_contract" type="date">
  Start of the underlying lease.
</ResponseField>

<ResponseField name="end_contract" type="date">
  End of the underlying lease. `null` for open-ended leases, which is the majority.
</ResponseField>

<ResponseField name="adjustment_threshold" type="string">
  Index change that must be reached before the rent may be adjusted, in the unit given by
  `adjustment_unit`. Decimal value serialized as a string.
</ResponseField>

<ResponseField name="adjustment_unit" type="string">
  Unit of `adjustment_threshold` — `"Prozent"` or `"Punkte"`.
</ResponseField>

<ResponseField name="passing_value" type="string">
  Share of the index change passed on to the rent, in percent (`"100.0000"` = fully passed on).
  Decimal value serialized as a string.
</ResponseField>

<ResponseField name="adjustment_locked" type="boolean">
  Whether adjustments are currently blocked for this agreement. Reflects the setting as of the
  last sync only — the source system keeps no history of it, so this value is the same on
  superseded states as on the current one.
</ResponseField>

<ResponseField name="adjustment_locked_until" type="date">
  Date up to which adjustments are blocked. Set independently of `adjustment_locked`, so check
  both.
</ResponseField>

<ResponseField name="notification_required" type="boolean">
  Whether the tenant must be notified before an adjustment takes effect.
</ResponseField>

<ResponseField name="adjustment_after_months" type="integer">
  Number of months that must pass before the next adjustment is permitted. Applies to
  `adjustment_type` `"Anpassung nach Ablauf Monaten"`.
</ResponseField>

<ResponseField name="calculation_period" type="integer">
  Length of the comparison period in months used to compute the index change.
</ResponseField>

<ResponseField name="recalculation_after_months" type="integer">
  Maximum number of months an adjustment may be applied retroactively.
</ResponseField>

<ResponseField name="comment" type="string">
  Free-text remark on the index agreement. `null` on most rows.
</ResponseField>

<ResponseField name="adjustment_type" type="string">
  How the adjustment date is determined — `"Anpassung zu Datum"` (on a fixed date) or
  `"Anpassung nach Ablauf Monaten"` (after `adjustment_after_months` have elapsed).
</ResponseField>
