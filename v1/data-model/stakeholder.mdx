The v1 Stakeholder domain covers four tables: `creditor`, `employees`, `owner`, and
`tenants`, all of which follow the [response structure](/v1/response-shape-conventions)
rules.

## creditor

`GET /v1/stakeholder/creditor` — vendor and creditor master data. This is the only
Stakeholder endpoint without a `property_id` column — a creditor is a standalone entity that
may serve multiple properties, referenced by `creditor_id` on other tables.

<ResponseField name="creditor_id" type="string" required>
  Unique creditor identifier.
</ResponseField>

<ResponseField name="name_1" type="string">
  Primary name line (company or last name).
</ResponseField>

<ResponseField name="name_2" type="string">
  Secondary name line.
</ResponseField>

<ResponseField name="type" type="string">
  Creditor type.
</ResponseField>

<ResponseField name="address_line_1" type="string">
  First line of the postal address, above `street_nr`.
</ResponseField>

<ResponseField name="street_nr" type="string">
  Street and house number.
</ResponseField>

<ResponseField name="zipcode_city" type="string">
  Postal code and city, combined into one field.
</ResponseField>

<ResponseField name="mail" type="string">
  Email address.
</ResponseField>

<ResponseField name="homepage" type="string">
  Website address.
</ResponseField>

<ResponseField name="contact_person" type="string">
  Named contact at the creditor.
</ResponseField>

<ResponseField name="phones" type="string[]">
  Phone numbers, as an array with one entry per number — same shape as
  `Stakeholder.tenants.phones`.
</ResponseField>

<ResponseField name="iban" type="string">
  Bank account IBAN.
</ResponseField>

<ResponseField name="swift" type="string">
  SWIFT/BIC code of the creditor's bank — the same thing `owner` calls `bic`.
</ResponseField>

<ResponseField name="bank" type="string">
  Bank name.
</ResponseField>

<ResponseField name="tax_id" type="string">
  Tax identification number.
</ResponseField>

<ResponseField name="exemption_certificate" type="boolean">
  Whether a construction-withholding-tax exemption certificate
  (`Freistellungsbescheinigung`, §48b EStG) is on file. Relevant when the creditor performs
  construction work.
</ResponseField>

<ResponseField name="exemption_certificate_date" type="date">
  Date on the exemption certificate. Which date it is — issued or expiring — is undocumented;
  contact support before relying on it.
</ResponseField>

<ResponseField name="industry" type="string">
  Industry classification.
</ResponseField>

<ResponseField name="industry_info" type="string">
  Additional industry detail. How it relates to `industry` is undocumented — contact support
  before relying on it.
</ResponseField>

<ResponseField name="okdn" type="string">
  Undocumented. Contact support before relying on it.
</ResponseField>

<ResponseField name="dms_link" type="string">
  Link to the creditor's document folder in the document management system, if attached.
</ResponseField>

## employees

`GET /v1/stakeholder/employees` — the property management team responsible for a property.

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="team" type="string">
  Team the employee belongs to, as a readable German name (e.g. `"Objektmanagement"`,
  `"Buchhaltung / Abrechnung"`). Matches
  [`Operations.projects.responsible_team`](/v1/data-model/operations), so that's how you
  resolve a project's team to its members. It does **not** match
  `Operations.notifications.responsible_team`, which holds numeric codes instead of names.
</ResponseField>

<ResponseField name="first_name" type="string">
  Employee first name.
</ResponseField>

<ResponseField name="last_name" type="string">
  Employee last name.
</ResponseField>

<ResponseField name="phone" type="string">
  Contact phone number.
</ResponseField>

<ResponseField name="mail" type="string">
  Contact email address.
</ResponseField>

<ResponseField name="inactive" type="boolean">
  Whether the employee record is inactive.
</ResponseField>

<Note>
  This is the assignment of people to properties, not a general employee directory: a property
  can have several rows (one per team involved), and the same person appears once per property
  they are responsible for. There is no employee identifier — match on `mail` if you need to
  deduplicate people across properties.
</Note>

## owner

`GET /v1/stakeholder/owner` — property owner master data, including ownership share for
co-owned properties.

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="debitor_id" type="integer" required>
  Owner identifier.
</ResponseField>

<ResponseField name="share" type="string" required>
  Ownership share as a percentage. Decimal value serialized as a string, not a JSON number
  — cast before doing arithmetic on it. A property can have multiple `owner` rows that sum
  to the total share.
</ResponseField>

<ResponseField name="salutation" type="string">
  Salutation/title.
</ResponseField>

<ResponseField name="name" type="string">
  Owner name (individual or company).
</ResponseField>

<ResponseField name="name_2" type="string">
  Secondary name line.
</ResponseField>

<ResponseField name="street_nr" type="string">
  Street and house number.
</ResponseField>

<ResponseField name="zipcode_city" type="string">
  Postal code and city, combined into one field.
</ResponseField>

<ResponseField name="phone" type="string">
  Contact phone number.
</ResponseField>

<ResponseField name="partner" type="string">
  Undocumented. Contact support before relying on it.
</ResponseField>

<ResponseField name="bank" type="string">
  Bank name.
</ResponseField>

<ResponseField name="fax" type="string">
  Fax number, if on file.
</ResponseField>

<ResponseField name="mail" type="string">
  Contact email address.
</ResponseField>

<ResponseField name="bic" type="string">
  Bank Identifier Code (BIC), if on file.
</ResponseField>

<ResponseField name="iban" type="string">
  Bank account IBAN.
</ResponseField>

<ResponseField name="account_number" type="string">
  Owner's account number for payouts. Unrelated to `Accounting.accounts.account_number`, which
  is a ledger account.
</ResponseField>

<Warning>
  Don't join `owner.debitor_id` to `creditor.creditor_id`. Both are numeric sequences and they
  overlap by coincidence — of the identifiers present in both, more than half belong to
  different parties. Owners and creditors are separate identifier spaces with no join key
  between them in `/v1/`.
</Warning>

## tenants

`GET /v1/stakeholder/tenants` — tenant master data and current lease terms.

<ResponseField name="property_id" type="string" required>
  Unique property identifier.
</ResponseField>

<ResponseField name="floor_area_person_id" type="integer" required>
  Unique identifier for this tenancy. Composed of `floor_area_id` and `person_id`, but use
  the field as given rather than deriving it yourself.
</ResponseField>

<ResponseField name="floor_area_id" type="integer">
  Unit the tenant occupies. References
  [`Property.property_structure.floor_area_id`](/v1/data-model/property#property_structure).
</ResponseField>

<ResponseField name="person_id" type="string" required>
  Tenant identifier, numbered per property rather than globally. `Accounting.booking_header`
  and `Accounting.booking_positions` reference it, so this is how you get from a booking to
  the tenant — join on `property_id` **and** `person_id` together, and cast
  `booking_positions.person_id` to a string first, since it comes back as a number there.
</ResponseField>

<ResponseField name="person_name" type="string">
  Full tenant name as a single field. No separate first/last name available.
</ResponseField>

<ResponseField name="name_1" type="string">
  First name line on the tenant record. Contact support before relying on its relationship
  to `person_name`.
</ResponseField>

<ResponseField name="name_2" type="string">
  Second name line on the tenant record, if present.
</ResponseField>

<ResponseField name="street_nr" type="string">
  Street and house number of the tenant's contact address.
</ResponseField>

<ResponseField name="zipcode_city" type="string">
  Postal code and city of the tenant's contact address, combined into one field.
</ResponseField>

<ResponseField name="contact_phone_main" type="string">
  Primary contact phone number.
</ResponseField>

<ResponseField name="contact_mail" type="string">
  Contact email address.
</ResponseField>

<ResponseField name="phones" type="string[]">
  Additional phone numbers, as an array with one entry per number.
</ResponseField>

<ResponseField name="iban" type="string">
  Tenant's bank account IBAN, if on file.
</ResponseField>

<ResponseField name="bank" type="string">
  Tenant's bank name, if on file.
</ResponseField>

<ResponseField name="contract_period" type="object">
  Lease term — `{start, end}` (date strings).
</ResponseField>

<ResponseField name="contract_end_option" type="date">
  Lease end date if an extension option is exercised.
</ResponseField>

<ResponseField name="option_valid_until" type="date">
  Deadline to exercise the extension option.
</ResponseField>

<ResponseField name="dms_link" type="string">
  Link to the lease document in the document management system, if attached.
</ResponseField>

<Note>
  To link a tenancy to a unit, join via `property_id` and `floor_area_id`.
  `floor_area_person_id` is the only field that identifies a row on its own — one person can
  hold several tenancies in the same property, so a join on `property_id` plus `person_id` can
  return more than one row per person. `floor_area_person_id` is also what
  [`Contracts.contract_debits`, `Contracts.contract_ends`, and
  `Contracts.index_rent`](/v1/data-model/contracts) reference — an integer here and on
  `contract_ends`/`index_rent`, but a string on `contract_debits`, so cast before joining
  against that one.
</Note>
