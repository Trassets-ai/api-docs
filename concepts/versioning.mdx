<mark>The Data API is served from two path families: `/v1/`, the versioned interface, and the original base path without a version prefix. The unversioned category and raw paths will be **switched off once the `/v1/` rollout is complete**. New integrations should use `/v1/` only.</mark>

## Current State

<mark>Tables are available under `/v1/`, e.g.:</mark>

```text
https://api.trassets.ai/v1/accounting/budgets
https://api.trassets.ai/v1/raw/sollart
```

<mark>Every `/v1/` route follows the [response structure](/v1/response-shape-conventions) rules. For the current list of available tables, check the **API Reference** tab under the `v1` version selector.</mark>

<mark>Until the switch-off, the same tables also remain available under the base path:</mark>

```text
https://api.trassets.ai/accounting/accounts
https://api.trassets.ai/raw/sollart
```

<mark>`GET /catalog` and `GET /changes` have no version prefix and are **not** affected by the switch-off.</mark>

<Warning>
  <mark>Once a table has a `/v1/` route, breaking changes land under a new prefix such as `/v2/`, not on the published path. The unversioned base paths carry no such guarantee.</mark>
</Warning>

## Migrating to /v1/

<mark>Migrate every table you use before the unversioned paths are switched off:</mark>

1. <mark>Check whether `/v1/{category}/{api_table}` exists for the table you use.</mark>
2. <mark>If it does, switch to it — the response shape differs from the base path (see [Response Structure](/v1/response-shape-conventions) and [Pagination](/v1/api-reference/introduction#pagination)).</mark>
3. <mark>Raw tables: switch from `/raw/{table_name}` to `/v1/raw/{table_name}` — same data, response key `total` instead of `total_rows`.</mark>

<mark>`/catalog` and `/changes` need no change.</mark>
