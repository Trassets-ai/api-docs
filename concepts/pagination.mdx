The Data API uses two pagination strategies depending on the endpoint type. Category endpoints support offset-based pagination, which is simple and predictable for dashboards and incremental fetches. Raw endpoints use cursor-based pagination, which stays stable even when the underlying data changes during a bulk export.

## Category Endpoint Pagination

Category endpoints accept `limit` and `offset` query parameters. The API returns pagination metadata in response headers so you can build next and previous page links without parsing the response body.

<ResponseField name="X-Total-Count" type="integer">
  Total number of rows matching the query, ignoring `limit` and `offset`.
</ResponseField>

<ResponseField name="X-Has-More" type="string">
  `"true"` or `"false"` — indicates whether more rows exist beyond the current page.
</ResponseField>

<ResponseField name="X-Next-Offset" type="integer">
  The offset to use for the next page. Only present when `X-Has-More` is `"true"`.
</ResponseField>

<ResponseField name="X-Next-Cursor" type="string">
  An opaque cursor for the next page. Present only when a full page was returned **and** the endpoint supports cursor pagination — see the note below. You can pass this as the `cursor` query parameter on the next request instead of using `offset`.
</ResponseField>

<Note>
  Every category endpoint supports cursor pagination. Rows are ordered by the configured sort
  column (or the primary key), `NULL` values last, with the internal row position (`ctid`) as
  tiebreaker — rows with equal values are neither skipped nor repeated. Tables without a sort
  column or primary key are paged by row position alone. Pass the `X-Next-Cursor` value unchanged
  as `cursor`; an altered cursor or one in an older format returns `400 Bad Request`,
  so restart from the first page. The row position is only stable within one sync run — see
  [Sync cycle](/concepts/sync-cycle).
</Note>

This example fetches page 2 with an offset of 100:

```bash
curl -G "https://api.trassets.ai/property/properties" \
  -H "X-API-Key: $TRASSETS_API_KEY" \
  -d "limit=100" \
  -d "offset=100"
```

## Raw Endpoint Pagination

Raw endpoints use cursor-based pagination via the `cursor` query parameter. The cursor value comes from the `next_cursor` field in the response body. Tables without a primary key are paged by row position (`ctid`), so every raw table can be exported completely. Within one sync run the cursor causes no duplicates or gaps; a reload in between (see [Sync cycle](/concepts/sync-cycle)) can shift row positions, so restart the export from the first page after a reload.

The response body contains these fields:

<ResponseField name="data" type="array">
  The array of rows for the current page.
</ResponseField>

<ResponseField name="count" type="integer">
  Number of rows in the current page.
</ResponseField>

<ResponseField name="next_cursor" type="string | null">
  The cursor to pass for the next page. When `null`, all rows have been fetched.
</ResponseField>

<ResponseField name="total_rows" type="integer">
  Total number of rows in the table.
</ResponseField>

The response also includes an `X-Snapshot-At` header with the ISO-8601 timestamp of the last successful sync for this table.

A cursor belongs to the snapshot it was issued for. If the table is re-synced while you paginate, the next request with that cursor returns `409 Conflict`. Restart the export from the first page (without `cursor`) — this way an export never silently mixes rows from two snapshots.

This example fetches the first page and then uses the cursor to continue:

```bash
# First page
curl -G "https://api.trassets.ai/raw/sollart" \
  -H "X-API-Key: $TRASSETS_API_KEY" \
  -d "limit=5000"

# Next page (use the next_cursor value from the previous response)
curl -G "https://api.trassets.ai/raw/sollart" \
  -H "X-API-Key: $TRASSETS_API_KEY" \
  -d "limit=5000" \
  -d "cursor=eyJjb2wiOiAiSERSX0lEIiwgInZhbCI6IDF9"
```

When `next_cursor` is `null`, the export is complete.

<Note>
  The maximum offset for category endpoints is 500,000. If you need to export more rows than that, switch to a raw endpoint or apply filters to reduce the result set.
</Note>
