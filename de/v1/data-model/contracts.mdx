Die v1-Contracts-Domäne umfasst fünf Tabellen: `service_contracts`, `contract_debits`,
`contract_debit_diffs`, `contract_ends` und `index_rent`, die alle den Regeln der
[Response-Struktur](/de/v1/response-shape-conventions) folgen.

## service_contracts

`GET /v1/contracts/service_contracts` — Wartungs- und Dienstleistungsverträge.

<ResponseField name="property_id" type="string" required>
  Eindeutige Objekt-ID.
</ResponseField>

<ResponseField name="creditor_id" type="string" required>
  Identifiziert den Dienstleister. Referenziert `Stakeholder.creditor` — siehe die
  [Stakeholder-Feldreferenz](/de/v1/data-model/stakeholder).
</ResponseField>

<ResponseField name="creditor_name" type="string">
  Anzeigename des Dienstleisters. In den meisten Zeilen `null` — verknüpfe stattdessen über
  `creditor_id` für einen zuverlässigen Namen.
</ResponseField>

<ResponseField name="contract_id" type="string" required>
  Vertrags-ID, ein formatierter String (z. B. `"2019/00015"`). Wird von
  [`Property.technical_objects.service_contract_id`](/de/v1/data-model/property)
  referenziert — so findest du den Vertrag zu einem bestimmten Aufzug, einer Heizungsanlage
  oder einer anderen Anlage.
</ResponseField>

<ResponseField name="contract_number" type="string">
  Lesbare Vertragsnummer.
</ResponseField>

<ResponseField name="contract_name" type="string">
  Vertragsname.
</ResponseField>

<ResponseField name="contract_category" type="string">
  Vertragskategorie.
</ResponseField>

<ResponseField name="contract_type" type="string">
  Vertragstyp.
</ResponseField>

<ResponseField name="contract_period" type="object">
  Vertragslaufzeit — `{start, end}` (Datumsstrings).
</ResponseField>

<ResponseField name="contract_value" type="string">
  Vertragswert. Dezimalwert als String serialisiert (z. B. `"0.0000"`), keine JSON-Zahl —
  vor Rechenoperationen casten.
</ResponseField>

<ResponseField name="contract_value_year" type="string">
  Auf ein Jahr normalisierter Vertragswert. Dezimalwert als String serialisiert, wie
  `contract_value`.
</ResponseField>

<ResponseField name="contract_reasoning" type="string">
  Begründungscode für den Vertrag.
</ResponseField>

<ResponseField name="contract_reasoning_comment" type="string">
  Freitextkommentar zur Vertragsbegründung.
</ResponseField>

## contract_debits

`GET /v1/contracts/contract_debits` — Mietsollstellungspositionen als Zeitreihe. Jeder
Datensatz repräsentiert eine geplante Sollstellung mit einem Gültigkeitsintervall.

<ResponseField name="property_id" type="string" required>
  Eindeutige Objekt-ID.
</ResponseField>

<ResponseField name="floor_area_id" type="string">
  Referenziert die Einheit in
  [`Property.property_structure`](/de/v1/data-model/property#property_structure). Hier ein
  String, während `property_structure.floor_area_id` ein Integer ist — vor dem Join casten.
</ResponseField>

<ResponseField name="floor_area_person_id" type="string">
  Identifiziert das Mietverhältnis, auf das sich diese Sollstellung bezieht. Derselbe Wert und
  derselbe Typ wie [`Stakeholder.tenants.floor_area_person_id`](/de/v1/data-model/stakeholder)
  — direkt verknüpfen, kein Cast nötig.
</ResponseField>

<ResponseField name="property_id_person_id" type="integer">
  Zusammengesetzter Schlüssel, der den Mieter identifiziert, auf den sich diese Sollstellung
  bezieht. Ähnelt einer Verkettung aus `property_id` und einer Personennummer, ist es aber
  nicht immer exakt — das Feld wie angegeben nutzen, nicht selbst herleiten. Nutze
  stattdessen `floor_area_person_id` oben, um zum Mieter zu gelangen — das ist ein
  dokumentierter Join-Schlüssel.
</ResponseField>

<ResponseField name="ledger_id" type="string">
  Sachkonto, auf das der Sollstellungstyp bucht.
</ResponseField>

<ResponseField name="debit_period" type="object">
  Gültigkeitsintervall der Sollstellung — `{start, end}` (Datumsstrings). `end` fehlt
  (statt `null` zu sein), solange das Intervall noch offen ist.
</ResponseField>

<ResponseField name="due_date_day" type="integer">
  Tag des Monats, an dem die Sollstellung fällig ist. `null`, wenn im Quellsystem kein
  Fälligkeitstag gesetzt ist.
</ResponseField>

<ResponseField name="debit_type" type="object">
  Kategorie der Sollstellung — `{code, label}` (z. B. `{"code": 11, "label":
  "Nettokaltmiete Wohnung"}`).
</ResponseField>

<ResponseField name="debit_amount" type="string" required>
  Der Sollstellungsbetrag für das Gültigkeitsintervall. Dezimalwert als String serialisiert,
  keine JSON-Zahl — vor Rechenoperationen casten.
</ResponseField>

<ResponseField name="account_group" type="string">
  Kontogruppen-Zuordnung. Steht in Beziehung zu, ist aber nicht abgeleitet von
  `kontenmapping_ranges`.
</ResponseField>

<ResponseField name="state" type="string">
  Status des Sollstellungsdatensatzes.
</ResponseField>

<ResponseField name="tax_type" type="boolean">
  Ob dieser Sollstellungstyp umsatzsteuerrelevant ist.
</ResponseField>

<ResponseField name="net_rent" type="boolean">
  Ob dieser Sollstellungstyp als Nettomiete klassifiziert ist, basierend auf dem für diesen
  Mandanten konfigurierten Kontenbereich.
</ResponseField>

<ResponseField name="side_costs" type="boolean">
  Ob dieser Sollstellungstyp als Nebenkosten klassifiziert ist, basierend auf dem für diesen
  Mandanten konfigurierten Kontenbereich.
</ResponseField>

## contract_debit_diffs

`GET /v1/contracts/contract_debit_diffs` — monatliche Abweichungen zwischen dem
Sollstellungsziel und den tatsächlichen Kontobewegungen. Nutze dies, um geplante
Sollstellungen mit dem realisierten Zahlungsfluss abzugleichen.

<ResponseField name="property_id" type="string" required>
  Eindeutige Objekt-ID.
</ResponseField>

<ResponseField name="debit_diff_value" type="object">
  Abweichungsbetrag — `{net, tax, gross}`.
</ResponseField>

<ResponseField name="person_id" type="string">
  Mieter oder Kontaktperson, mit der diese Abweichung verknüpft ist, nach einem lokalen,
  pro Objekt vergebenen Nummernschema — über `property_id` **und** `person_id` gemeinsam
  verknüpfen, genau wie bei
  [`Accounting.booking_header.person_id`](/de/v1/data-model/accounting).
</ResponseField>

<ResponseField name="account_id" type="integer">
  Sachkonto, auf das sich die Abweichung bezieht. Verknüpft sich mit
  [`Accounting.accounts.account_id`](/de/v1/data-model/accounting).
</ResponseField>

<ResponseField name="valid_from" type="date" required>
  Monat, auf den sich die Abweichung bezieht.
</ResponseField>

<ResponseField name="debit_diff_reminder_from" type="date">
  Datum, von dem an eine Zahlungserinnerung für diese Abweichung gilt, falls vorhanden.
</ResponseField>

<ResponseField name="debit_diff_reminder_manual" type="boolean">
  Ob das obige Erinnerungsdatum manuell gesetzt wurde statt automatisch berechnet.
</ResponseField>

## contract_ends

`GET /v1/contracts/contract_ends` — Mietvertragsenden und die Handhabung von
Verlängerungen/Optionen. Nutze dies, um anstehende Vertragsabläufe, Fristen für die
Ausübung von Optionen und den aktuellen Ausübungsstatus zu verfolgen.

<Note>
  Dieser Endpunkt verlangt den Query-Parameter `property_id` — eine Anfrage ohne ihn
  beantwortet die API mit `400 Bad Request`. Es ist der einzige `/v1/`-Endpunkt mit einem
  Pflichtfilter.
</Note>

<ResponseField name="floor_area_person_id" type="string" required>
  Identifiziert das Mietverhältnis, auf das sich dieser Datensatz bezieht. Derselbe Wert und
  derselbe Typ wie [`Stakeholder.tenants.floor_area_person_id`](/de/v1/data-model/stakeholder)
  und das `contract_debits.floor_area_person_id` dieser Domäne — über beide direkt verknüpfen,
  kein Cast nötig.
</ResponseField>

<ResponseField name="floor_area_id" type="integer">
  Referenziert die Einheit in
  [`Property.property_structure`](/de/v1/data-model/property#property_structure).
</ResponseField>

<ResponseField name="property_id" type="string" required>
  Eindeutige Objekt-ID.
</ResponseField>

<ResponseField name="contract_end_id" type="string" required>
  Kennung für diesen spezifischen Options-/Verlängerungseintrag — ein Mietverhältnis kann
  mehrere haben. Deterministisch bei unveränderten Rohdaten, aber nicht über den
  Lebenszyklus stabil: abgeleitet unter anderem aus `option_deadline` und dem
  Mietvertragsende, ändert sich also, wenn eines der beiden später revidiert wird.
</ResponseField>

<ResponseField name="period" type="object">
  Mietvertragslaufzeit — `{start, end}` (Datumsstrings). `end` ist das tatsächliche
  Vertragsende nach Anwendung jeglicher Optionslogik, nicht das rohe vertragliche Enddatum.
  Ein fehlender Key (statt `null`) bedeutet, dass diese Grenze nicht gesetzt ist.
</ResponseField>

<ResponseField name="option_state" type="object">
  Status der Verlängerungsoption — `{code, label}` (Codes: `1` = Offen, `2` = Ausgeübt,
  `3` = Nicht ausgeübt, `4` = Abgelaufen). `{}`, wenn für diesen Datensatz kein
  Optionseintrag vorhanden ist — das wie fehlenden Code/Label behandeln.
</ResponseField>

<ResponseField name="option_remarks" type="string[]">
  Freitextanmerkungen zur Option, als Array mit einem Eintrag pro Anmerkung. Leer, wenn
  keine vorhanden sind.
</ResponseField>

<ResponseField name="contract_end_new" type="date">
  Nicht dokumentiert. Vor der Nutzung beim Support nachfragen.
</ResponseField>

<ResponseField name="contract_prolongation_months" type="integer">
  Verlängerungsdauer in Monaten.
</ResponseField>

<ResponseField name="request_date" type="date">
  Datum, an dem der Mieter aufgefordert wurde, über eine Verlängerungsoption zu
  entscheiden.
</ResponseField>

<ResponseField name="response_deadline" type="date">
  Frist für die Antwort des Mieters.
</ResponseField>

<ResponseField name="tenant_response_date" type="date">
  Datum, an dem der Mieter tatsächlich geantwortet hat.
</ResponseField>

<ResponseField name="response_type" type="integer">
  Nicht dokumentiert. Vor der Nutzung beim Support nachfragen.
</ResponseField>

<ResponseField name="option_deadline" type="date">
  Frist, bis zu der eine Verlängerungsoption ausgeübt werden muss.
</ResponseField>

<ResponseField name="deadline_lead_time" type="integer">
  Nicht dokumentiert. Vor der Nutzung beim Support nachfragen.
</ResponseField>

<ResponseField name="auto_use_option" type="boolean">
  Ob die Option automatisch ausgeübt wird, wenn der Mieter nicht antwortet.
</ResponseField>

<ResponseField name="options_used" type="integer">
  Anzahl der bereits genutzten Verlängerungsoptionen.
</ResponseField>

<ResponseField name="options_not_used" type="integer">
  Anzahl der noch verfügbaren Verlängerungsoptionen.
</ResponseField>

<ResponseField name="is_terminated" type="boolean">
  Ob für dieses Mietverhältnis ein Kündigungsgrund hinterlegt ist.
</ResponseField>

<ResponseField name="termination_reason" type="string">
  Kündigungsgrund, falls das Mietverhältnis gekündigt wurde.
</ResponseField>

## index_rent

`GET /v1/contracts/index_rent` — Indexmietvereinbarungen: an welchen Verbraucherpreisindex eine
Miete gekoppelt ist, welche Schwellen und Regeln eine Anpassung auslösen und in welchem Zeitraum
der jeweils vereinbarte Stand gilt. Eine Zeile pro Mietverhältnis × Sollart × Index-Stand;
überholte Stände bleiben in der Tabelle — filtere auf `is_current` für den heute gültigen Stand.

<ResponseField name="property_id" type="string" required>
  Eindeutige Objekt-ID.
</ResponseField>

<ResponseField name="floor_area_person_id" type="string" required>
  Identifiziert das Mietverhältnis, für das die Vereinbarung gilt. Derselbe Wert und derselbe
  Typ wie [`Stakeholder.tenants.floor_area_person_id`](/de/v1/data-model/stakeholder),
  `contract_debits.floor_area_person_id` und `contract_ends.floor_area_person_id` — überall
  direkt verknüpfen, kein Cast nötig.
</ResponseField>

<ResponseField name="validity_period" type="object">
  Gültigkeitszeitraum dieses Index-Stands — `{start, end}` (Datumsstrings). `end` ist
  `"9999-12-31"` (ein Platzhalterdatum, nicht `null`), solange der Stand offen ist — das gilt für
  jede Zeile mit `is_current` = `true`.
</ResponseField>

<ResponseField name="calculation_model" type="object">
  Regel, die bestimmt, ab wann eine Anpassung wirksam wird — `{code, label}`. Codes: `1` = nach
  BGB ($557b), `2` = Ab Berechnungsdatum (beide Bedingungen), `3` = Ab Berechnungsdatum
  (mindestens eine Bedingung), `4` = Ab Mitteilungsdatum (beide Bedingungen), `5` = Ab
  Mitteilungsdatum (mindestens eine Bedingung), `6` = zum nächsten Quartal (beide Bedingungen),
  `7` = zum nächsten Quartal (mindestens eine Bedingung). `code` `0` bedeutet, dass im
  Quellsystem kein Modell gesetzt ist, und kommt mit `label: null`.
</ResponseField>

<ResponseField name="is_current" type="boolean">
  Ob dies der aktuell gültige Stand ist. `false` kennzeichnet einen überholten Stand, der zur
  Historie erhalten bleibt.
</ResponseField>

<ResponseField name="account_id" type="integer">
  Die Sollart, für die die Indexvereinbarung gilt — derselbe Code wie
  [`contract_debits.debit_type.code`](#contract_debits) (z. B. `11` = Nettokaltmiete Wohnung,
  `12` = Gewerbemiete (m. USt.)). Trotz des Namens **kein** Sachkonto: Das Feld verknüpft nicht
  mit [`Accounting.accounts.account_id`](/de/v1/data-model/accounting), obwohl beide Integer sind
  — siehe [Feldglossar](/de/v1/data-model/field-glossary).
</ResponseField>

<ResponseField name="index_name" type="string">
  Bezeichnung des Preisindex, an den die Miete gekoppelt ist, wie im Quellsystem gepflegt (z. B.
  `"VPI 2020"`, `"Verbraucherpreisindex"`). Freitext, keine feste Codeliste, und `null`, wenn
  kein Index benannt ist.
</ResponseField>

<ResponseField name="base_year" type="integer">
  Basisjahr dieses Index (z. B. `2020`).
</ResponseField>

<ResponseField name="index_value_used" type="string">
  Indexwert zu Beginn des Indexbezugs, der als Vergleichsbasis dient. Dezimalwert als String
  serialisiert, keine JSON-Zahl — vor Rechenoperationen casten. `null`, wenn die Indexreihe für
  diesen Monat keinen Wert enthält.
</ResponseField>

<ResponseField name="min_date" type="date">
  Beginn des vertragsbereinigten Gültigkeitsfensters. Entspricht `validity_period.start` — außer
  beim frühesten Stand eines Mietverhältnisses, wo es bis `begin_contract` zurückreicht, falls
  der Vertrag früher begann.
</ResponseField>

<ResponseField name="max_date" type="date">
  Ende des vertragsbereinigten Gültigkeitsfensters: `validity_period.end`, begrenzt auf
  `end_contract`. `"9999-12-31"`, wenn der Stand offen ist und kein Vertragsende hinterlegt ist.
  Nutze `min_date`/`max_date` für eine lückenlose Tagesabdeckung über ein Mietverhältnis und
  `validity_period` für die rohen Grenzen des Stands.
</ResponseField>

<ResponseField name="begin_contract" type="date">
  Beginn des zugrunde liegenden Mietvertrags.
</ResponseField>

<ResponseField name="end_contract" type="date">
  Ende des zugrunde liegenden Mietvertrags. `null` bei unbefristeten Verträgen — das ist die
  Mehrheit.
</ResponseField>

<ResponseField name="adjustment_threshold" type="string">
  Indexveränderung, die erreicht sein muss, bevor die Miete angepasst werden darf, in der Einheit
  aus `adjustment_unit`. Dezimalwert als String serialisiert.
</ResponseField>

<ResponseField name="adjustment_unit" type="string">
  Einheit von `adjustment_threshold` — `"Prozent"` oder `"Punkte"`.
</ResponseField>

<ResponseField name="passing_value" type="string">
  Anteil der Indexveränderung, der an die Miete weitergegeben wird, in Prozent (`"100.0000"` =
  vollständige Weitergabe). Dezimalwert als String serialisiert.
</ResponseField>

<ResponseField name="adjustment_locked" type="boolean">
  Ob Anpassungen für diese Vereinbarung derzeit gesperrt sind. Gibt nur den Stand des letzten
  Syncs wieder — das Quellsystem führt dazu keine Historie, deshalb steht auf überholten Ständen
  derselbe Wert wie auf dem aktuellen.
</ResponseField>

<ResponseField name="adjustment_locked_until" type="date">
  Datum, bis zu dem Anpassungen gesperrt sind. Unabhängig von `adjustment_locked` gesetzt —
  prüfe beide Felder.
</ResponseField>

<ResponseField name="notification_required" type="boolean">
  Ob der Mieter vor Wirksamwerden einer Anpassung benachrichtigt werden muss.
</ResponseField>

<ResponseField name="adjustment_after_months" type="integer">
  Anzahl der Monate, die vor der nächsten zulässigen Anpassung verstreichen müssen. Gilt bei
  `adjustment_type` = `"Anpassung nach Ablauf Monaten"`.
</ResponseField>

<ResponseField name="calculation_period" type="integer">
  Länge des Vergleichszeitraums in Monaten, über den die Indexveränderung berechnet wird.
</ResponseField>

<ResponseField name="recalculation_after_months" type="integer">
  Maximale Anzahl Monate, um die eine Anpassung rückwirkend angewendet werden darf.
</ResponseField>

<ResponseField name="comment" type="string">
  Freitextbemerkung zur Indexvereinbarung. In den meisten Zeilen `null`.
</ResponseField>

<ResponseField name="adjustment_type" type="string">
  Wie das Anpassungsdatum bestimmt wird — `"Anpassung zu Datum"` (zu einem festen Datum) oder
  `"Anpassung nach Ablauf Monaten"` (nach Ablauf von `adjustment_after_months`).
</ResponseField>
