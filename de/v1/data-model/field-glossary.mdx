description: "Referenzleitfaden zu Feldnamen, die über mehrere /v1/-Tabellen hinweg vorkommen, einschließlich property_id, person_id, creditor_id, floor_area_person_id und den mehrdeutigen Feldern account_name und period."
---

Dieses Glossar definiert Feldnamen, die auf mehr als einer im [v1 Datenmodell](/de/v1/data-model/overview)
dokumentierten `/v1/`-Tabelle vorkommen. Nutze es als schnelle Referenz beim Verknüpfen über
`/v1/`-Tabellen hinweg — mehrere dieser Felder haben je nach Tabelle unterschiedliche
Bedeutungen, genau deshalb lohnt sich der Blick hierher.

| Feld | Typ | Beschreibung |
| --- | --- | --- |
| `property_id` | string | Eindeutige Objekt-ID; primärer Verknüpfungsschlüssel über jede `/v1/`-Tabelle und auf allen gegen `properties` auflösbar. |
| `person_id` | string oder integer | Identifiziert einen Mieter oder eine Kontaktperson. `booking_header`, `booking_positions`, `tenants` und `contract_debit_diffs` teilen einen ID-Raum, der pro Objekt vergeben wird — über `property_id` **und** `person_id` gemeinsam verknüpfen und `booking_positions.person_id` (eine Zahl) vorher in einen String casten. `notifications.person_id` ist eine separate Sequenz aus einem anderen Subsystem und gehört nicht in diesen ID-Raum. |
| `floor_area_person_id` | string | Identifiziert ein bestimmtes Mietverhältnis. Kommt bei `tenants`, `contract_debits`, `contract_ends` und `index_rent` vor und ist auf allen vier derselbe zugrunde liegende Wert mit demselben Typ — direkt über dieses Feld verknüpfen, ohne Objekt-Scoping und ohne Cast. Zusammengesetzt aus `floor_area_id` und `person_id` — das Feld wie angegeben nutzen, nicht selbst herleiten. |
| `creditor_id` | string | Identifiziert einen Kreditor (Lieferant oder Dienstleister). Referenziert `Stakeholder.creditor` — siehe die [Stakeholder-Feldreferenz](/de/v1/data-model/stakeholder). Bei `projects` unzuverlässig; siehe die [Operations-Feldreferenz](/de/v1/data-model/operations). |
| `floor_area_id` | integer oder string | Referenziert [`Property.property_structure`](/de/v1/data-model/property#property_structure). Kommt bei `technical_objects`, `tenants`, `contract_ends` und `property_structure` selbst als Integer vor — außer bei `contract_debits`, dort als String; vor dem Join casten. |
| `account_id` | integer oder string | Interne Sachkonto-ID. Ein einheitlicher Join-Key bei `accounts`, `booking_positions`, `budgets` und `contract_debit_diffs` — alle verknüpfen sich mit `accounts.account_id`; siehe die [Accounting-Feldreferenz](/de/v1/data-model/accounting). Zwei Tabellen verwenden den Namen für etwas anderes: `property_structure.account_id` ist ein fachlicher String-Schlüssel auf Strukturknoten (siehe die [Property-Feldreferenz](/de/v1/data-model/property#property_structure)), und `index_rent.account_id` ist ein Sollart-Code, der `contract_debits.debit_type.code` entspricht — ein Integer wie der Sachkonto-Schlüssel, aber aus einem anderen Wertebereich, weshalb ein Join gegen `accounts` unbemerkt leer bleibt (siehe die [Contracts-Feldreferenz](/de/v1/data-model/contracts#index_rent)). |
| `account_number` | string | Lesbare Kontonummer bei `accounts` und `budgets` — nicht mit `account_id` oben verwechseln, das ist ein anderer (interner) Wert. |
| `account_name` | string | **Mehrdeutig über Tabellen hinweg — kein einheitliches Konzept.** Bei `accounts` der Name des Kontos im Kontenplan. Bei `depreciation/assets` die Rechnungslegungsgrundlage, unter der eine Abschreibung gebucht ist (z. B. `"Handelsrecht"` vs. `"Steuerrecht"`). Bei `property_structure` der Anzeigename des Strukturknotens (Kostenstellen- oder Einheitenname). Drei unabhängige Konzepte mit demselben Feldnamen. |
| `period` | object | **Mehrdeutig über Tabellen hinweg — kein einheitliches Konzept.** Bei `booking_positions` der Buchungszeitraum (`{start, end}`) einer Buchung. Bei `contract_ends` die Mietvertragslaufzeit (`{start, end}`), wobei `end` das optionsbereinigte tatsächliche Enddatum ist, nicht das rohe vertragliche Enddatum. |
| `property_structure_account_id` | string | Fremdschlüssel auf [`Property.property_structure`](/de/v1/data-model/property#property_structure), passend zu dessen `account_id`. Bei `booking_header` und `booking_positions` immer befüllt und der einzige Weg, eine Buchung auf eine Einheit herunterzubrechen. Bei `technical_objects` der Fallback für Zeilen ohne `floor_area_id`. |
| `cost_center_id` | string | Kostenstellen-Referenz. Kommt bei `notifications` und `projects` vor; es gibt noch keinen `/v1/`-Kostenstellen-Endpunkt, um sie aufzulösen. |
| `booking_date` | date | ISO-8601-Datum der Buchhaltungsbuchung. Kommt bei `booking_header` und `booking_positions` vor. |
| `dms_link` | string | Link zum zugehörigen Dokument im Dokumentenmanagementsystem, falls vorhanden. Kommt bei `booking_header`, `creditor`, `properties`, `property_structure` und `tenants` vor. |
