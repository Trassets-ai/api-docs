Die v1-Accounting-Domäne umfasst vier Tabellen: `accounts`, `booking_header`,
`booking_positions` und `budgets`. Alle vier folgen den Regeln der
[Response-Struktur](/de/v1/response-shape-conventions) — verschachtelte
`period`-/`amount`-Objekte und flache Join-Keys.

<Note>
  `kontenmapping_ranges` hat noch keinen `/v1/`-Endpunkt — bis dahin über
  [`Accounting.kontenmapping_ranges`](/de/data-model/accounting#kontenmapping_ranges)
  abrufen.
</Note>

## accounts

`GET /v1/accounting/accounts` — der Kontenplan.

<ResponseField name="property_id" type="string" required>
  Eindeutige Objekt-ID.
</ResponseField>

<ResponseField name="account_id" type="integer" required>
  Interne Konto-ID. Wird von `booking_positions` und `budgets` als `account_id` referenziert.
</ResponseField>

<ResponseField name="account_number" type="string">
  Lesbare Kontonummer. Bei manchen Zeilen `null` (z. B. Summen-/Sammelkonten).
</ResponseField>

<ResponseField name="account_name" type="string">
  Kontoname.
</ResponseField>

<ResponseField name="account_balance_type" type="object">
  Saldoseiten-Code des Kontos — `{code, label}` (z. B. `{"code": 1, "label":
  "Aufwandskonto"}`). `label` fehlt bei manchen `code`-Werten.
</ResponseField>

<ResponseField name="account_type_name" type="string">
  Lesbarer Kontotyp.
</ResponseField>

<ResponseField name="account_group" type="string">
  Kontogruppenzuordnung. Verwandt mit, aber nicht abgeleitet aus `kontenmapping_ranges`.
</ResponseField>

<ResponseField name="accounting_entity" type="string">
  Nicht dokumentiert. Möglicherweise derselbe Join-Begriff wie
  `Property.properties.accounting_property_id` — vor einer Verknüpfung darauf beim Support
  nachfragen.
</ResponseField>

<ResponseField name="account_tax_code" type="integer">
  Nicht dokumentierter Steuer-Code. Vor der Nutzung beim Support nachfragen.
</ResponseField>

<ResponseField name="account_tax_appliance" type="integer">
  Nicht dokumentierter Steuer-Code. Vor der Nutzung beim Support nachfragen.
</ResponseField>

## booking_header

`GET /v1/accounting/booking_header` — Hauptbuch-Buchungsköpfe. Kein `period`- oder
`amount`-Objekt: Die Tabelle hat nur ein einzelnes `booking_date`-Feld und ein einzelnes
`booking_value`-Feld, die beiden Konventionen greifen hier strukturell nicht.

<ResponseField name="property_id" type="string" required>
  Eindeutige Objekt-ID.
</ResponseField>

<ResponseField name="booking_header_id" type="integer" required>
  Eindeutige ID des Buchungskopfs. `booking_positions` referenziert dies als
  `booking_header_id`.
</ResponseField>

<ResponseField name="booking_nr" type="integer">
  Buchungsnummer.
</ResponseField>

<ResponseField name="creditor_id" type="string">
  Mit der Buchung verknüpfter Kreditor. Referenziert `Stakeholder.creditor` — siehe die
  [Stakeholder-Feldreferenz](/de/v1/data-model/stakeholder).
</ResponseField>

<ResponseField name="person_id" type="string">
  Mit der Buchung verknüpfter Mieter oder Ansprechpartner, mit lokaler, objektbezogener
  Nummerierung. Verknüpft sich mit `Stakeholder.tenants` über `property_id` **und**
  `person_id` gemeinsam — nie über `person_id` allein, da die Nummerierung pro Objekt neu
  beginnt. Nicht jede Person ist ein Mieter, manche Zeilen haben deshalb keinen Treffer.
  Nicht mit demselben ID-Raum wie `person_id` auf `Operations.notifications` verwechseln —
  dort ist es eine eigenständige Sequenz aus einem anderen Subsystem.
</ResponseField>

<ResponseField name="booking_date" type="date">
  Datum der Buchung.
</ResponseField>

<ResponseField name="booking_value" type="number">
  Gesamtwert des Buchungskopfs.
</ResponseField>

<ResponseField name="m2" type="number">
  Mit der Buchung verbundene Fläche in Quadratmetern, falls zutreffend.
</ResponseField>

<ResponseField name="booking_text" type="string">
  Freitextbeschreibung der Buchung.
</ResponseField>

<ResponseField name="initial_booking_text" type="string">
  Ursprünglicher Buchungstext, vor einer eventuellen späteren Korrektur.
</ResponseField>

<ResponseField name="booking_barcode" type="string">
  Barcode-Referenz auf das Buchungsdokument, falls gescannt.
</ResponseField>

<ResponseField name="dms_link" type="string">
  Link zum Buchungsdokument im Dokumentenmanagementsystem, falls vorhanden.
</ResponseField>

<ResponseField name="cost_center_id_name_concat" type="string">
  Kombinierte Kostenstellen-ID und -name — die einzige Quelle dieses Labels; es gibt kein
  separates ID/Name-Paar, gegen das sich stattdessen verknüpfen ließe.
</ResponseField>

<ResponseField name="ledger_id_name_concat" type="string">
  Kombinierte Konto-ID und -name, aus demselben Grund wie `cost_center_id_name_concat`.
</ResponseField>

<ResponseField name="person_name_concat" type="string">
  Kombinierte Personen-ID und -name, aus demselben Grund wie `cost_center_id_name_concat`.
</ResponseField>

<ResponseField name="property_structure_account_id" type="string">
  Fremdschlüssel auf `Property.property_structure`, entspricht
  `property_structure.account_id`. Immer befüllt und der einzige Weg, eine Buchung auf eine
  einzelne Einheit herunterzubrechen — `booking_header` führt kein `floor_area_id`.
  `property_structure` hat noch keinen `/v1/`-Endpunkt, also über den unversionierten Pfad
  abrufen.
</ResponseField>

## booking_positions

`GET /v1/accounting/booking_positions` — einzelne Buchungspositionen, über
`booking_header_id` mit einem Kopf verknüpft.

<ResponseField name="property_id" type="integer" required>
  Eindeutige Objekt-ID. Hier eine Zahl, während `properties.property_id` und die meisten
  anderen Tabellen sie als String zurückgeben — beide als String vergleichen.
</ResponseField>

<ResponseField name="booking_position_id" type="integer" required>
  Eindeutige ID der Position.
</ResponseField>

<ResponseField name="booking_header_id" type="integer" required>
  ID des übergeordneten Buchungskopfs. Verknüpft sich mit
  `booking_header.booking_header_id`.
</ResponseField>

<ResponseField name="account_id" type="integer" required>
  Konto, auf das die Position gebucht wird. Verknüpft sich mit `accounts.account_id` oben.
</ResponseField>

<ResponseField name="contra_account_id" type="integer">
  Gegenkonto für die Buchung.
</ResponseField>

<ResponseField name="contra_account_name" type="string">
  Name des Gegenkontos. Nicht über eine Verknüpfung von `contra_account_id` mit `accounts`
  ableitbar — die beiden entsprechen sich nicht.
</ResponseField>

<ResponseField name="creditor_id" type="integer">
  Mit der Position verknüpfter Kreditor. Referenziert `Stakeholder.creditor` — siehe die
  [Stakeholder-Feldreferenz](/de/v1/data-model/stakeholder). Hier eine Zahl, während
  `creditor.creditor_id` ein String ist, also vor dem Join casten.
</ResponseField>

<ResponseField name="person_id" type="integer">
  Mit der Position verknüpfter Mieter oder Ansprechpartner. Verknüpft sich mit
  `Stakeholder.tenants` über `property_id` **und** `person_id` gemeinsam — die Nummerierung
  beginnt pro Objekt neu — und der Wert muss vorher in einen String gecastet werden, da
  `tenants.person_id` ein String ist. Nicht jede Person ist ein Mieter, manche Zeilen haben
  deshalb keinen Treffer.
</ResponseField>

<ResponseField name="property_id_person_id" type="integer">
  Zusammengesetzter Schlüssel, der den Mieter identifiziert, auf den sich diese Position
  bezieht. Ähnelt einer Verkettung von `property_id` und `person_id`, ist aber nicht immer
  exakt das — nutze das Feld wie geliefert, statt es selbst abzuleiten. Keine `/v1/`-Tabelle
  hat ein passendes Gegenstück, für den Weg zum Mieter also `property_id` plus `person_id`
  nutzen.
</ResponseField>

<ResponseField name="period" type="object">
  Buchungszeitraum — `{start, end}` (Datumsstrings).
</ResponseField>

<ResponseField name="amount" type="object">
  Buchungsbetrag — `{net, tax, gross}`.
</ResponseField>

<ResponseField name="amount_per_sqm" type="object">
  Buchungsbetrag, pro Quadratmeter normalisiert — `{net, tax, gross}`.
</ResponseField>

<ResponseField name="account_group" type="string">
  Kontogruppenzuordnung.
</ResponseField>

<ResponseField name="booking_date" type="date">
  Datum der Buchung.
</ResponseField>

<ResponseField name="booking_nr" type="integer">
  Buchungsnummer.
</ResponseField>

<ResponseField name="booking_Lfd_nr" type="integer">
  Laufende Positionsnummer innerhalb der Buchung.
</ResponseField>

<ResponseField name="booking_type" type="integer">
  Buchungstyp-Code.
</ResponseField>

<ResponseField name="booking_position_text" type="string">
  Freitextbeschreibung der Position.
</ResponseField>

<ResponseField name="sh" type="string">
  Soll/Haben-Kennzeichen (`S`/`H`). Nicht aus dem Vorzeichen von `amount.net` ableiten —
  rund 3,55 % der Zeilen (Storno-/Korrekturbuchungen) haben ein Vorzeichen, das diesem
  Kennzeichen widerspricht.
</ResponseField>

<ResponseField name="HNDL" type="string">
  Dezimalwert als String serialisiert (z. B. `"0.0000"`), keine JSON-Zahl — vor
  Rechenoperationen casten. Nicht dokumentiert: rund 99,2 % der Zeilen sind `"0.0000"`, und
  wo ungleich null, liegt der Wert meist nahe an `amount.net` bei Buchungstypen im Umfeld
  umlagefähiger Betriebskosten. Vor der Nutzung beim Support nachfragen.
</ResponseField>

<ResponseField name="property_structure_account_id" type="string">
  Fremdschlüssel auf `Property.property_structure`, entspricht
  `property_structure.account_id` — derselbe immer befüllte Einheiten-Join-Key wie bei
  `booking_header`.
</ResponseField>

## budgets

`GET /v1/accounting/budgets` — Budgetbeträge, eine Zeile pro Objekt, Konto und Monat.

<ResponseField name="property_id" type="string" required>
  Eindeutige Objekt-ID.
</ResponseField>

<ResponseField name="account_id" type="integer" required>
  Konto, für das das Budget gilt. Verknüpft sich mit `accounts.account_id` oben.
</ResponseField>

<ResponseField name="account_number" type="integer">
  Lesbare Kontonummer. Hier ein Integer, während `accounts.account_number` ein String ist —
  für einen Abgleich zwischen beiden Tabellen als String vergleichen.
</ResponseField>

<ResponseField name="date" type="date" required>
  Monat, für den die Budgetzeile gilt.
</ResponseField>

<ResponseField name="budget" type="string" required>
  Budgetbetrag für den jeweiligen Monat und das jeweilige Konto. Dezimalwert als String
  serialisiert (z. B. `"24862.3300"`), keine JSON-Zahl — vor Rechenoperationen casten.
</ResponseField>
