Die Data API nutzt ein einfaches API-Key-Schema. Du übergibst deinen Key im `X-API-Key`-Header bei jedem Request. Der Key bestimmt, auf welchen Kunden-Scope und welche Datenstufen du zugreifen kannst.

## Einen Key erstellen

Trassets richtet den Portal-Zugang für deine Organisation ein; eine öffentliche Registrierung gibt es nicht. Mit diesem Zugang meldet sich ein Administrator deiner Organisation unter [portal.api.trassets.ai](https://portal.api.trassets.ai) an und erzeugt API-Keys selbst über das Dashboard. Der Klartext-Key wird genau einmal angezeigt. Kopiere ihn sofort und speichere ihn in einem sicheren Secrets-Manager. Wenn du ihn verlierst, musst du den alten Key widerrufen und einen neuen erzeugen.

## Den Key in Requests übergeben

Füge den `X-API-Key`-Header bei jedem Call hinzu. Hier ein minimales curl-Beispiel gegen eine live `/v1/`-Tabelle:

```bash
curl "https://api.trassets.ai/v1/property/technical_objects?limit=1" \
  -H "X-API-Key: $TRASSETS_API_KEY"
```

## Key-Typen

Jeder Key hat einen Typ, `raw` oder `transformed`. Der Typ entscheidet, ob der Key Raw-Quelltabellen lesen darf. Ein Administrator setzt ihn im Portal; für Kunden angelegte Keys sind `transformed`.

| Endpunkt | `raw`-Key | `transformed`-Key |
| --- | --- | --- |
| Category-Endpunkte (`/{category}/{table}`) | <mark>alle Daten; personenbezogene Spalten nur mit passendem Grant</mark> | <mark>alle Daten, im Rahmen der am Key konfigurierten Einschränkungen; personenbezogene Spalten nur mit passendem Grant</mark> |
| `GET /raw/{table_name}` und `/v1/raw/{table_name}` | <mark>200 mit beiden Grants für personenbezogene Daten, sonst 403</mark> | 403 |
| `GET /raw/tables` und `/v1/raw/tables` | Liste der Tabellen | leere Liste |
| `GET /catalog` | alle Kategorien und Tabellen | nur die Kategorien und Tabellen, auf die der Key zugreifen darf |
| `GET /changes` | alle geänderten Tabellen | nur geänderte Tabellen innerhalb der Kategorien und Tabellen des Keys; `?category=X` außerhalb davon liefert 403 |

<mark>Ein `raw`-Key kann keine Einschränkungen tragen. Zum Lesen einer Raw-Tabelle braucht er zusätzlich beide Grants für personenbezogene Daten, `personal` und `personal_financial`, weil sich Raw-Tabellen nicht spaltenweise filtern lassen; `/raw/tables` listet die Tabellen in jedem Fall. Ein `transformed`-Key bekommt keine Rohdaten und keine Tabellen ohne Kategorie.</mark>

<mark>Ist `/raw/tables` leer, obwohl der Key gültig ist, ist der Key `transformed`. Liefert eine Raw-Tabelle 403 mit `detail` "Raw export requires an API key of type raw with personal data grants. Contact your administrator or Trassets support.", ist der Key `transformed` oder ihm fehlt einer der beiden Grants — frag deinen Administrator oder den Trassets-Support. Ein geänderter Key-Typ oder Grant wirkt nach etwa einer Minute.</mark>

### Grants für personenbezogene Daten

<mark>Spalten mit personenbezogenen Daten — Namen, Kontakt- und Bankdaten von Mietern, Eigentümern, Mitarbeitern und Kreditoren — gehören zu einer von zwei Klassen, `personal` und `personal_financial`. Ein Key sieht eine Klasse nur mit dem passenden Grant; `personal` schließt `personal_financial` nicht ein. Ohne Grant liefert `/v1/{category}/{table}` die Zeilen ohne diese Spalten. ID-Spalten und `property_id` bleiben immer erhalten.</mark>

<mark>Grants gelten für jeden Key, `raw` oder `transformed`, und haben Vorrang vor einem Spaltenfilter, der die Spalte nennt. Die unversionierten Category-Endpunkte sind nicht betroffen. Raw-Tabellen brauchen beide Grants (siehe oben). Ein Administrator setzt Grants im Portal; eine Änderung wirkt nach etwa einer Minute.</mark>

## Speicherung und Sicherheit des Keys

Trassets speichert deinen API-Key niemals im Klartext. Auf unseren Servern wird nur ein HMAC-SHA-256-Hash zur Verifikation aufbewahrt. Das bedeutet: Wir können einen Key nach der Erstellung nicht wiederherstellen oder erneut anzeigen.

Behandle deinen Key wie ein Passwort:

- Committe ihn nicht in die Versionskontrolle.
- Rotiere Keys regelmäßig: Erzeuge im Portal einen neuen Key, stelle deine Integration um und lösche dann den alten. Eine Ein-Klick-Rotation gibt es nicht.
- Beschränke jeden Key auf die minimal nötige Zugriffsstufe für deine Integration.

## Authentifizierungsfehler

Wenn der Key fehlt, ungültig ist oder nicht die erforderliche Zugriffsstufe hat, liefert die API eine RFC-7807-Problem-Antwort.

### 401 Unauthorized

```json
{
  "type": "about:blank",
  "title": "Unauthorized",
  "status": 401,
  "detail": "API key required",
  "instance": "/v1/property/technical_objects"
}
```

Das bedeutet, dass der Request keinen `X-API-Key`-Header enthielt.

### 403 Forbidden

```json
{
  "type": "about:blank",
  "title": "Forbidden",
  "status": 403,
  "detail": "API key is disabled",
  "instance": "/v1/property/technical_objects"
}
```

Eine 403-Antwort bedeutet, dass der Key nicht akzeptiert wird: Er ist unbekannt (`Invalid API key`) oder deaktiviert (`API key is disabled`), oder er ist gültig, aber der angeforderte Endpunkt oder die Datenstufe ist nicht in deinem Abonnement enthalten. Das Feld `detail` zeigt, welcher Fall vorliegt. Kontaktiere deinen Account-Administrator oder den Trassets-Support, um deinen Zugang zu ändern.
