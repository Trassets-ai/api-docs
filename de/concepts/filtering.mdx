Die Data API hat zwei unabhängige Filterachsen: welche **Zeilen** zurückkommen, gesteuert von dir per Query-Parameter, und welche **Spalten** zurückkommen, gesteuert von einem Admin pro API-Key.

## Zeilenfilterung (horizontal)

Category-Endpunkte akzeptieren Query-Parameter, die nach den filterbaren Spalten benannt sind — jeder davon ist ein exakter Match. Welche Spalten filterbar sind, variiert pro Endpunkt; die genaue Liste steht im Tab **API-Referenz** beim jeweiligen Endpunkt.

```text
GET /property/properties?city=Berlin&use_type=Wohnen
GET /contracts/contract_debits?property_id=1234&date_begin=2024-01-01
```

Es gibt keine Bereichs-, Wildcard- oder `OR`-Syntax — ein Query-Parameter matcht Zeilen, bei denen diese Spalte exakt dem angegebenen Wert entspricht. Mehrere Parameter lassen sich kombinieren und werden UND-verknüpft.

### Pflichtfilter

Filter sind bei fast jedem Endpunkt optional, einige verlangen aber einen und beantworten eine Anfrage ohne ihn mit `400 Bad Request`:

```json
{ "detail": "Missing required filter(s): ['property_id']" }
```

Aktuell betrifft das `/contracts/contract_ends` (und die `/v1/`-Variante) — dort ist `property_id` immer nötig. Pflichtparameter sind pro Endpunkt im Tab **API-Referenz** als erforderlich markiert; verlasse dich also darauf statt auf die Annahme, ein ungefilterter Aufruf funktioniere.

<Note>
  Raw-Endpunkte (`/raw/{table_name}`) unterstützen diese Filter nicht — sie liefern immer die vollständige, unfilterte Tabelle, paginiert per Cursor. Siehe [Endpoint Types](/de/concepts/endpoint-types).
</Note>

## Spaltenfilterung (vertikal)

Welche Felder in der Response einer Entität enthalten sind, kann pro API-Key eingeschränkt werden. Ein Admin konfiguriert das im Trassets-Portal, pro Key und pro Entität — ein Key ohne explizite Konfiguration liefert den vollen, in der **API-Referenz** dokumentierten Spaltenumfang. Änderungen wirken sofort.

Das ist nicht über den Request selbst steuerbar — es gibt keinen `fields`- oder `select`-Query-Parameter. Fehlt ein erwartetes Feld in der Response, obwohl es in der API-Referenz für diese Entität steht, liegt das wahrscheinlich an der Spaltenkonfiguration deines API-Keys — wende dich an den Trassets-Support, um sie zu prüfen oder zu ändern.
