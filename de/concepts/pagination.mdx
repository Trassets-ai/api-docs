Die Data API nutzt zwei Pagination-Strategien, abhängig vom Endpunkt-Typ. Category-Endpunkte unterstützen Offset-basierte Pagination, die für Dashboards und inkrementelle Abrufe einfach und vorhersehbar ist. Raw-Endpunkte nutzen Cursor-basierte Pagination, die auch dann stabil bleibt, wenn sich die zugrunde liegenden Daten während eines Bulk-Exports ändern.

## Pagination für Category-Endpunkte

Category-Endpunkte akzeptieren die Query-Parameter `limit` und `offset`. Die API liefert Pagination-Metadaten in Response-Headern, sodass du Links zur nächsten und vorherigen Seite bauen kannst, ohne den Response-Body zu parsen.

<ResponseField name="X-Total-Count" type="integer">
  Gesamtzahl der Zeilen, die der Query entsprechen, unabhängig von `limit` und `offset`.
</ResponseField>

<ResponseField name="X-Has-More" type="string">
  `"true"` oder `"false"` — gibt an, ob über die aktuelle Seite hinaus weitere Zeilen existieren.
</ResponseField>

<ResponseField name="X-Next-Offset" type="integer">
  Der Offset für die nächste Seite. Nur vorhanden, wenn `X-Has-More` gleich `"true"` ist.
</ResponseField>

<ResponseField name="X-Next-Cursor" type="string">
  Ein undurchsichtiger Cursor für die nächste Seite. Nur vorhanden, wenn eine vollständige Seite zurückgegeben wurde **und** der Endpunkt Cursor-Pagination unterstützt — siehe den Hinweis unten. Du kannst diesen anstelle von `offset` als `cursor`-Query-Parameter im nächsten Request übergeben.
</ResponseField>

<Note>
  Jeder Category-Endpunkt unterstützt Cursor-Pagination. Die Zeilen sind nach der konfigurierten
  Sortierspalte (oder dem Primärschlüssel) sortiert, `NULL`-Werte zuletzt, mit der internen
  Zeilenposition (`ctid`) als Tiebreaker — Zeilen mit gleichem Wert werden weder übersprungen noch
  wiederholt. Tabellen ohne Sortierspalte und Primärschlüssel werden allein nach Zeilenposition
  paginiert. Übergib den Wert aus `X-Next-Cursor` unverändert als `cursor`; ein veränderter
  Cursor oder einer im älteren Format liefert `400 Bad Request` — starte
  dann bei der ersten Seite neu. Die Zeilenposition ist nur innerhalb eines Sync-Laufs stabil, siehe
  [Sync-Zyklus](/de/concepts/sync-cycle).
</Note>

Dieses Beispiel ruft Seite 2 mit einem Offset von 100 ab:

```bash
curl -G "https://api.trassets.ai/property/properties" \
  -H "X-API-Key: $TRASSETS_API_KEY" \
  -d "limit=100" \
  -d "offset=100"
```

## Pagination für Raw-Endpunkte

Raw-Endpunkte nutzen Cursor-basierte Pagination über den Query-Parameter `cursor`. Der Cursor-Wert stammt aus dem `next_cursor`-Feld im Response-Body. Tabellen ohne Primärschlüssel werden nach Zeilenposition (`ctid`) paginiert, sodass sich jede Raw-Tabelle vollständig exportieren lässt. Innerhalb eines Sync-Laufs entstehen durch den Cursor keine Duplikate oder Lücken; ein Reload dazwischen (siehe [Sync-Zyklus](/de/concepts/sync-cycle)) kann Zeilenpositionen verschieben — starte den Export nach einem Reload daher bei der ersten Seite neu.

Der Response-Body enthält diese Felder:

<ResponseField name="data" type="array">
  Das Array der Zeilen für die aktuelle Seite.
</ResponseField>

<ResponseField name="count" type="integer">
  Anzahl der Zeilen auf der aktuellen Seite.
</ResponseField>

<ResponseField name="next_cursor" type="string | null">
  Der Cursor, der für die nächste Seite übergeben werden soll. Wenn `null`, wurden alle Zeilen abgerufen.
</ResponseField>

<ResponseField name="total_rows" type="integer">
  Gesamtzahl der Zeilen in der Tabelle.
</ResponseField>

Die Antwort enthält außerdem einen `X-Snapshot-At`-Header mit dem ISO-8601-Zeitstempel des letzten erfolgreichen Syncs für diese Tabelle.

Ein Cursor gehört zu dem Snapshot, für den er ausgegeben wurde. Wird die Tabelle während deiner Pagination neu synchronisiert, liefert die nächste Anfrage mit diesem Cursor `409 Conflict`. Starte den Export dann neu ab der ersten Seite (ohne `cursor`) — so mischt ein Export nie still Zeilen aus zwei Snapshots.

Dieses Beispiel ruft die erste Seite ab und nutzt dann den Cursor, um fortzufahren:

```bash
# First page
curl -G "https://api.trassets.ai/raw/sollart" \
  -H "X-API-Key: $TRASSETS_API_KEY" \
  -d "limit=5000"

# Next page (use the next_cursor value from the previous response)
curl -G "https://api.trassets.ai/raw/sollart" \
  -H "X-API-Key: $TRASSETS_API_KEY" \
  -d "limit=5000" \
  -d "cursor=eyJjb2wiOiAiSERSX0lEIiwgInZhbCI6IDF9"
```

Wenn `next_cursor` `null` ist, ist der Export abgeschlossen.

<Note>
  Der maximale Offset für Category-Endpunkte beträgt 500.000. Wenn du mehr Zeilen exportieren musst, als das erlaubt, wechsle zu einem Raw-Endpunkt oder wende Filter an, um die Ergebnismenge zu reduzieren.
</Note>
