Die Trassets Data API ist eine REST-Schnittstelle für Immobilien- und Marktdaten. Basis-URL: `https://api.trassets.ai`. Sende deinen API-Key im `X-API-Key`-Header bei jedem Request. Alle Antworten sind JSON, sofern nicht anders angegeben.

## Endpunkt-Typen

Die API bietet zwei Endpunkt-Familien. Wähle die, die zu deinem Anwendungsfall passt.

| Typ | Pfad-Muster | Pagination | Anwendungsfall |
| --- | --- | --- | --- |
| Category-Endpunkte | `/{category}/{api_table}` | Offset-basiert (`limit` / `offset`) plus Cursor-Unterstützung | Business-Abfragen, Dashboards, inkrementelle Abrufe |
| Raw-Endpunkte | `/raw/{table_name}` | Cursor-basiert (`cursor` aus `next_cursor` im Body) | Bulk-Sync, vollständige Exporte, Data Warehousing |

### Category-Endpunkte

Category-Endpunkte liefern normalisierte, geschäftsfertige Daten. Sie unterstützen die Query-Parameter `limit` und `offset`, mit Metadaten in den Response-Headern:

- `X-Total-Count` — Gesamtzahl der Zeilen, die zur Abfrage passen
- `X-Has-More` — `"true"` oder `"false"`
- `X-Next-Offset` — der Offset für die nächste Seite
- `X-Next-Cursor` — ein opaker Cursor, wenn eine volle Seite zurückgegeben wird

### Raw-Endpunkte

Raw-Endpunkte legen vollständige Quelltabellen ungefiltert offen. Die Pagination ist Cursor-basiert über den Query-Parameter `cursor`, entnommen aus dem Feld `next_cursor` im Response-Body. Die maximale Seitengröße beträgt 10.000 Zeilen. Der Header `X-Snapshot-At` gibt den Zeitstempel des letzten erfolgreichen Syncs für diese Tabelle an, sodass jede Zeile innerhalb einer Cursor-Sequenz zu diesem Snapshot konsistent ist.

## Fehlerformat

Fehler folgen [RFC 7807](https://datatracker.ietf.org/doc/html/rfc7807) (`application/problem+json`). Jedes Fehlerobjekt enthält `type`, `title`, `status`, `detail` und `instance`. Siehe [Fehler](/de/concepts/errors) für eine vollständige Liste der Status-Codes und Hinweise zu Wiederholungsversuchen.

## Versionierung

Die API liegt derzeit auf dem Basis-Pfad. URL-Versionierung unter `/v1/` ist geplant, aber noch nicht verbindlich. Solange die Versionierung nicht aktiv ist, können Breaking Changes auftreten. Wir empfehlen, deine Integration am dokumentierten Verhalten auszurichten und den Changelog auf Updates zu beobachten.
